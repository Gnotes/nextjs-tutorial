    一、Server Actions、Streaming 与中间件

    Q1：Server Actions 是什么？原理上它和传统表单提交 / API 路由有什么区别？

    【考察点】是否理解「在服务端执行的表单 / 事件动作」这一新范式，以及它如何省去手写接口。

    【参考答案】

    • 定义：Server Actions 是 Next.js 提供的能力——在服务端组件里定义一个加了 "use server" 标记的异步函数，前端表单 / 按钮直接调用它，框架负责把请求序列化到服务端执行并返回结果，不需要你手写 API 路由。
    • 原理：本质是一个 POST 请求打到当前路由，服务端执行该函数、重渲染相关组件、返回新的 UI 数据流；配合 React 的 useActionState / useFormStatus 处理加载态与错误。
    • 对比：相比手写 REST 接口，它省去了接口定义、类型手写、错误码对齐；相比传统 HTML 表单，它带状态更新和类型安全。适合「写评论、提交表单、点赞」这类紧贴 UI 的写操作。
    app/actions.ts
    'use server'

export async function createPost(formData: FormData) {
  const title = formData.get('title')
  // 直接在服务端写库，无需手写 API 路由
  await db.post.create({ data: { title } })
  // 执行后自动触发相关页面的数据重新验证
  revalidatePath('/blog')
}

    Q2：Streaming（流式渲染）和 Suspense 是什么关系？解决了什么问题？

    【考察点】是否理解「HTML 分段下发、按需加载」相比「整页一次性渲染」的体验提升。

    【参考答案】

    • 问题：传统 SSR 要等整棵组件树数据都就绪才输出第一字节，慢组件会拖垮整个页面（请求瀑布）。
    • 方案：Streaming 把 HTML 切成多个 chunk 边渲染边下发；用 <Suspense> 包裹慢组件，先给它一个 loading 占位，其余部分先到先展示。
    • 效果：用户更快看到首屏外壳，内容分块渐进出现——这就是 Next.js App Router 默认开启的渲染方式。

    Q3：中间件（Middleware）执行在什么位置？典型用途有哪些？

    【考察点】是否知道中间件在请求到达页面前执行，以及 matcher 匹配的写法。

    【参考答案】

    • 位置：middleware.ts 在请求匹配路由之前运行，可用于鉴权重定向、国际化路由、Cookie 处理、日志等。它运行在边缘运行时（Edge Runtime）。
    • 写法：导出默认函数，用 NextResponse.redirect / next() 控制走向；用 config.matcher 限定匹配路径，避免对静态资源无谓执行。
    • 坑：matcher 写错会让中间件对所有请求生效，增加延迟；边缘运行时没有 Node.js 完整 API（以官方文档为准）。

    Q4：Edge Runtime 和 Node.js Runtime 有什么区别？怎么选？

    【考察点】对两种运行时模型的理解，边缘计算的取舍。

    【参考答案】

    • Edge Runtime：运行在靠近用户的边缘节点，启动快、全局分布式，但 API 子集受限（不能用原生 Node 模块、不支持长连接）。适合中间件、轻量 SSR。
    • Node.js Runtime：完整 Node 环境，可用全部生态与原生模块，适合重计算、数据库直连。
    • 选型：中间件默认边缘；页面默认 Node；只在确认需要低延迟且逻辑轻量时切边缘。

    二、性能优化与安全

    Q5：Next.js 里你会做哪些性能优化？怎么衡量？

    【考察点】是否有体系化优化手段，而非只说「加载更快」。

    【参考答案】

    • 衡量：用 Web Vitals 指标——最大内容绘制 LCP、交互到首次输入延迟 INP、累积布局偏移 CLS。
    • 手段清单：next/image 自动尺寸 + 格式 + 懒加载；next/font 自托管字体避免布局偏移；next/script 第三方脚本按策略加载；路由级 loading.tsx + Suspense 流式；动态 import 做代码分割；缓存策略（ISR / Data Cache）减少重复渲染；避免在客户端组件拉取巨型依赖。

    Q6：next/image 相比普通 img 做了哪些优化？

    【考察点】对图片优化体系的细节掌握。

    【参考答案】：自动输出现代格式（WebP / AVIF）、按视口生成多尺寸响应式图、默认懒加载、占位避免布局偏移（CLS）、配合 CDN 按需裁剪。坑：必须显式给 width / height 或 fill，否则报错；远程图片要在 next.config 配置允许的域名。

    Q7：如何防跨站脚本（XSS）？什么是内容安全策略（CSP）？

    【考察点】安全基础 + Next.js 对 CSP 的支持。

    【参考答案】

    • XSS 防护：React 默认转义插值内容；不要用 dangerouslySetInnerHTML 渲染不可信内容；必须渲染富文本时先做服务端消毒（sanitize）。
    • CSP（Content Security Policy，内容安全策略）：通过响应头声明允许加载的脚本 / 样式 / 图片来源，浏览器据此阻止内联脚本与未授权源执行，是防 XSS 的纵深防线。Next.js 支持通过中间件或 headers 配置 CSP；使用带随机数（nonce）的 CSP 时，内联脚本需要携带对应 nonce（以官方文档为准）。

    Q8：环境变量的 NEXT_PUBLIC_ 前缀有什么意义？密钥放哪才安全？

    【考察点】是否理解客户端 / 服务端环境变量的边界，避免泄露密钥。

    【参考答案】

    • 只有带 NEXT_PUBLIC_ 前缀的环境变量才会被打进客户端 bundle；无前缀的只存在于服务端。
    • 原则：密钥（数据库密码、第三方 Secret Key）永远不加前缀、只在服务端组件 / Server Actions / 路由处理程序里读取；误把密钥加了 NEXT_PUBLIC_ 会随 JS 暴露给所有用户。

    Q9：error.tsx、not-found.tsx、loading.tsx 分别解决什么？

    【考察点】对文件约定式 UI 状态边界的掌握。

    【参考答案】：loading.tsx 是路由段加载时的 Suspense 兜底 UI；error.tsx 是该段运行时报错的错误边界（客户端组件，带重置能力）；not-found.tsx 处理 notFound() 抛出的 404。三者按目录层级作用于对应路由段。

    三、部署与工程化

    Q10：Next.js 有哪些部署模式？静态导出（output: 'export'）有什么限制？

    【考察点】部署形态认知与边界。

    【参考答案】

    • 模式：Vercel 一键部署（默认，自动优化）、自托管 Node 服务器（next start）、Docker 容器、静态导出。
    • 静态导出：output: 'export' 把站点构建成纯 HTML / 静态文件，可挂任意静态托管。代价：不支持服务端渲染、ISR、路由处理程序动态逻辑、中间件等依赖服务器运行时的能力（以官方文档为准）。

    Q11：Turbopack 是什么？和 webpack 比有什么优势？

    【考察点】跟进构建工具演进的情况。

    【参考答案】：Turbopack 是 Vercel 用 Rust 开发的 Next.js 新一代打包器，定位为 webpack 的继任者，主打更快的冷启动与热更新（HMR）速度。next dev --turbo 的开发模式已稳定；生产构建能力随版本推进（以官方文档为准）。面试时不要说成「已经全面替代 webpack」——如实说明它在开发模式已可用、生产能力在完善即可。

    Q12：如果让你排查「线上页面首屏慢」，你的排查路径是什么？

    【考察点】综合题，看是否有系统化排查思路。

    【参考答案】：按从外到内、从测量到优化的顺序——

    ① 测指标
    LCP / INP / CLS
    →
    ② 看网络瀑布
    找慢请求
    →
    ③ 分类定位
    数据 / 渲染 / 资源
    →
    ④ 对应手段优化并复测
    • 数据慢 → 查数据库查询、加缓存 / ISR、Suspense 拆分慢组件；渲染慢 → 看是否整页阻塞，改流式；资源大 → 图片 / 字体 / 第三方脚本优化、代码分割。
    本篇速记清单›

    ① Server Actions = 免手写接口的服务端函数；② Streaming + Suspense 边下边渲；③ 中间件在路由前、跑在边缘；④ Edge 快但 API 受限；⑤ 性能看 Web Vitals 四件套；⑥ next/image 自动优化；⑦ CSP 是 XSS 纵深防线；⑧ NEXT_PUBLIC_ 会暴露到客户端；⑨ loading/error/not-found 三文件约定；⑩ output:'export' 牺牲服务端能力换纯静态；⑪ Turbopack 是 Rust 新打包器；⑫ 首屏慢：测指标 → 找瀑布 → 分类优化。
