    概念与背景

    静态博客本身没有后端数据库，评论系统通常有三种选择：用托管的第三方服务、借一个现成平台（如 GitHub Discussions）、或自己建库写接口。对个人技术博客，"借平台"是性价比最高的——不用维护后端，还能利用平台自带的身份与反垃圾能力。

    方案对比

    常见博客评论方案
    方案原理与优点缺点
    Giscus基于 GitHub Discussions；免费、无需后端、可与深色模式联动访客需有 GitHub 账号；数据在 GitHub
    utterances基于 GitHub Issues，同类方案更轻量GitHub 已停止在主页推广 issues 评论；功能比 Giscus 少
    Disqus老牌托管评论，功能全、接入简单免费版插广告、加载慢、偏重
    自建 + 数据库完全可控，可自定义表单与审核流要写接口、做反垃圾、维护存储，成本最高

    结论：技术博客首选 Giscus——读者多半有 GitHub 账号，且它开源、无广告、支持主题跟随。本节以此为主线。

    Giscus 工作原理

    Giscus 把每篇文章映射成 GitHub 仓库里的一条 Discussion：页面通过 pathname 或 URL 与 Discussion 对应，访客评论时会跳转授权 GitHub OAuth，评论内容其实写在你公开仓库的 Discussions 里。

    文章页 /blog/hello-world
    →
    giscus 小脚本
    按 pathname 匹配
    →
    对应仓库的
    一条 Discussion
    →
    访客 GitHub 授权
    发表评论

    接入前的仓库配置

    1. 建一个公开的 GitHub 仓库（可以就是博客源码仓库），并在 Settings → General → Features 里开启 Discussions。
    2. 到 github.com/apps/giscus 安装 giscus 应用，授权它访问该仓库。
    3. 打开 giscus.app，填入仓库地址；工具会自动查出 repository ID 与所选 Discussion 分类的 category ID——这两个值后面组件要用。

    封装评论组件

    用官方 React 组件库 @giscus/react，把它包成一个 Comments 组件。关键是让 theme 跟随第 54 节 next-themes 的当前主题，实现深浅色联动。

    终端
    npm install @giscus/react
    components/Comments.tsx
    "use client";

import Giscus from "@giscus/react";
import { useTheme } from "next-themes";

export function Comments() {
  const { resolvedTheme } = useTheme();   // 第 54 节的主题
  // 主题联动：博客暗色 -> giscus 用 dark，亮色用 light
  const theme = resolvedTheme === "dark" ? "dark" : "light";

  return (
    <section className="mt-12 border-t border-gray-200 pt-8 dark:border-gray-700">
      <Giscus
        repo="your-name/my-blog"                 // 你的公开仓库
        repoId="R_kgDOxxxxxxxx"                   // giscus.app 生成的仓库 ID
        category="Announcements"                  // Discussion 分类名
        categoryId="DIC_kwDOxxxxxxxx"             // 分类 ID
        mapping="pathname"                        // 按路径匹配 Discussion
        reactionsEnabled="1"
        emitMetadata="0"
        inputPosition="top"
        theme={theme}                            // 跟随博客深浅色
        lang="zh-CN"
        loading="lazy"
      />
    </section>
  );
}

    评论与静态生成的关系

    评论是客户端动态加载的：文章页面在 next build 时被静态预渲染，但评论内容并不在构建时写进 HTML，而是访客打开页面时由 Giscus 的脚本实时拉取。这意味着：

    • 静态页面本身不随评论数增长而变大——性能不受评论量影响。
    • 新评论对访客立即可见，不需要重新构建站点。
    • 代价是首屏要额外加载一个第三方 iframe/脚本，所以组件里设了 loading="lazy"，配合第 56 节优化避免拖累 LCP。

    审核与反垃圾

    关注点做法
    谁能评论Giscus 要求登录 GitHub，天然挡掉了大部分匿名垃圾评论。
    预审核在 giscus.app 设置里开启"评论需手动审核后显示"，或把评论放到需审批的 Discussion 分类。
    违规处理直接在 GitHub Discussions 里删除或锁定对应讨论，全站同步生效。
    常见坑›
    • 仓库必须是公开的，且已开启 Discussions 并安装 giscus 应用，否则组件加载报错。
    • repoId / categoryId 是一串自动生成的 ID，不要手填仓库名当 ID。
    • 主题联动必须用 resolvedTheme（最终生效主题），否则 system 模式下判断不准。
    最佳实践›
    • 把 Giscus 配置放进环境变量（NEXT_PUBLIC_GISCUS_REPO_ID 等），避免硬编码进组件。
    • 评论区懒加载，长文章里放在正文后面，不抢占首屏。
    • 维护一个单独的评论仓库或分类，与博客源码仓库隔离，便于批量管理。
