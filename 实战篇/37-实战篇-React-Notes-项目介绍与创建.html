    项目背景：认识 React Notes

    React Notes（官方仓库 vercel/server-components-notes-demo）是 React 团队最初编写、后由 Vercel 移植到 Next.js App Router 的一个笔记应用演示，线上地址为 next-rsc-notes.vercel.app。它最初的目的不是做一个产品，而是用一个有交互、有数据、有写操作的真实小应用，演示 React Server Components (RSC) 与服务端渲染在实际项目里长什么样：左侧是笔记列表，右侧是选中笔记的预览/编辑，支持新建、编辑、搜索，以及登录与附件。

    本教程 37-50 节就围绕这个形态，手写一个自己的 react-notes。为了把重点放在 Next.js 的能力上、而不是被重型数据库拖慢，我们把官方 demo 里的托管键值数据库（Vercel KV，基于 Redis）换成本地 SQLite：零运维、单文件、启动即有，最适合边学边写。官方 demo 的 GitHub OAuth 登录我们放到第 44 节再扩展。

    技术选型

    一个"跟着写"的项目，选型原则是：能用框架自带能力就不引第三方库，必须引的只引最主流的那一个。本项目最终技术栈如下：

    关注点选型理由
    路由与渲染Next.js App Router本教程主线，天然支持 React Server Components、流式渲染
    语言TypeScript（TS）笔记数据结构清晰，类型能避免改库时到处传错字段
    数据库SQLite + better-sqlite3单文件、无需起服务；better-sqlite3 是同步、API 极简的绑定，适合服务端组件里直接查询
    写操作接口Route Handlers（路由处理程序）用 app/api/**/route.ts 暴露 POST/PUT，前端 fetch 调用
    Markdown 渲染marked + sanitize-htmlmarked 把 Markdown 转 HTML；因为 marked 不做清洗，需 sanitize-html 去除危险标签
    样式原生 CSS / 内联 style把注意力放在数据与路由上，不引入 Tailwind 学习成本

    注意：官方 demo 用的是 Vercel KV（Redis）与 Prisma；我们这里用 better-sqlite3 直接写结构化查询语言（Structured Query Language，SQL），到第 46 节再讲如何把它替换成 Prisma，思路完全一致。

    用 create-next-app 初始化

    打开终端，新建一个名为 react-notes 的工程。下面的命令一行行执行即可（npx 是 Node 自带的包执行器）：

    终端（bash/zsh）
    # 1. 用官方脚手架创建 App Router + TypeScript 项目
npx create-next-app@latest react-notes --typescript --eslint --app --no-tailwind --no-src-dir --no-import-alias

# 2. 进入目录
cd react-notes

# 3. 安装数据与 Markdown 相关依赖
#    better-sqlite3：SQLite 的 Node 同步绑定（原生模块）
#    marked：Markdown -> HTML
#    sanitize-html：清洗 HTML，防 XSS
npm install better-sqlite3 marked sanitize-html
npm install -D @types/better-sqlite3 @types/sanitize-html

# 4. 启动开发服务器
npm run dev
# 打开 http://localhost:3000 看到默认页面即成功
    说明：参数怎么选›

    --app 表示启用 App Router；--no-src-dir 表示不建 src/ 目录，直接用根目录下的 app/（本教程统一这样）；--no-tailwind 表示不装 Tailwind，我们用少量原生 CSS 即可。如果你喜欢 src 目录或 Tailwind，也可以选，代码里的相对路径相应调整即可。

    数据模型设计

    一张 notes 表就够了。每条笔记有：主键 id（用 UUID 字符串，避免暴露自增数量）、title 标题、body Markdown 正文、created_at / updated_at 两个时间戳（存毫秒数，排序方便）。

    lib/db.ts（数据库连接 + 建表 + 基础 CRUD）
    import Database from "better-sqlite3";
import path from "path";

// data/notes.db 位于项目根目录，首次运行自动创建
const dbDir = path.join(process.cwd(), "data");
import fs from "node:fs";
fs.mkdirSync(dbDir, { recursive: true });

const db = new Database(path.join(dbDir, "notes.db"));

// 建表：IF NOT EXISTS 保证重复执行不报错
db.exec(`
  CREATE TABLE IF NOT EXISTS notes (
    id         TEXT PRIMARY KEY,
    title      TEXT NOT NULL DEFAULT '',
    body       TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
  );
`);

export type Note = {
  id: string;
  title: string;
  body: string;
  created_at: number;
  updated_at: number;
};

/** 列表：按更新时间倒序 */
export function getAllNotes(): Note[] {
  return db
    .prepare("SELECT id, title, body, created_at, updated_at FROM notes ORDER BY updated_at DESC")
    .all() as Note[];
}

/** 单条：查不到返回 undefined */
export function getNote(id: string): Note | undefined {
  return db
    .prepare("SELECT * FROM notes WHERE id = ?")
    .get(id) as Note | undefined;
}

/** 新建：返回新笔记 */
export function createNote(): Note {
  const id = crypto.randomUUID();
  const now = Date.now();
  db.prepare(
    "INSERT INTO notes (id, title, body, created_at, updated_at) VALUES (?, ?, ?, ?, ?)"
  ).run(id, "Untitled", "", now, now);
  return getNote(id)!;
}

/** 更新标题与正文，顺带刷新 updated_at */
export function updateNote(id: string, title: string, body: string): void {
  db.prepare(
    "UPDATE notes SET title = ?, body = ?, updated_at = ? WHERE id = ?"
  ).run(title, body, Date.now(), id);
}

export default db;

    几个要点：better-sqlite3 的 .prepare().run()/.get()/.all() 都是同步的，这在 Next.js 服务端组件里反而省事——直接 await 一个普通函数甚至不用 await，结果立即可用。查询参数一律用 ? 占位符绑定，绝不字符串拼接，从根上杜绝 SQL 注入。

    常见坑：better-sqlite3 是原生模块›

    better-sqlite3 包含 C++ 原生代码，安装时会编译。如果 npm install 报错，通常是缺少编译工具链（macOS 装 Xcode 命令行工具 xcode-select --install）。另外注意：它是服务端专用模块，绝不能被客户端组件（带 "use client" 的文件）直接 import，否则会把 Node 内置模块打进浏览器包报错。所有对 lib/db 的调用都放在服务端组件或 Route Handler 里。

    最佳实践：把 data/ 与依赖写进 .gitignore›

    data/notes.db 是运行时数据，不应提交进 Git；node_modules 同理。在 .gitignore 里加一行 /data。这样别人 clone 后首次 npm run dev，lib/db.ts 里的 CREATE TABLE IF NOT EXISTS 会自动把表建好，开箱即用。

    提示：为什么用 crypto.randomUUID()›

    Node.js 19+ 与现代浏览器都全局提供 crypto.randomUUID()，无需再装 uuid 包。它生成的是 RFC 4122 标准 UUID 字符串，如 "3f8c…"，作为 URL 里 /notes/[id] 的参数天然合适，也不会像自增整数那样暴露笔记总数。
