    概念与背景

    博客是最适合用 Next.js 实践静态站点生成（SSG）的场景：文章内容相对固定、发布频率不高、对首屏速度与搜索引擎优化（Search Engine Optimization，SEO）要求高。与其接一套内容管理系统（Content Management System，CMS）或数据库，最直接的方式是把每篇文章写成一个 Markdown（Markdown Text）文件，放在仓库里，构建时读取并渲染成静态页面。

    本系列我们统一围绕一个名为 my-blog 的项目展开（App Router、TypeScript、Tailwind CSS）。它的目标形态是：作者在 content/posts/ 下新建 .md 文件写文章，提交后自动生成 /blog/<slug> 页面，并出现在 /blog 列表页中。后续 52-57 节会在这个骨架上逐步叠加 Contentlayer 数据层、SEO、深色模式、多语言、性能分析与评论。

    内容约定与解析工具

    每篇 Markdown 文件由两部分组成：顶部的 frontmatter（前置元数据） 与下方的正文。frontmatter 是夹在两行 --- 之间的 YAML（YAML Ain't Markup Language） 片段，用来存放标题、日期、摘要、标签等结构化信息。

    content/posts/hello-world.md
    ---
title: "你好，世界"
date: "2026-10-20"
description: "my-blog 的第一篇文章，记录从零搭建博客的过程。"
tags: ["Next.js", "博客"]
---

## 为什么写这个博客

这里是 Markdown 正文……可以写 **加粗**、列表，以及一个代码块：

```bash
npm run dev
```

正文会被渲染成 HTML。

    解析管线用的是 unified 生态：gray-matter 负责拆出 frontmatter 与正文，remark 把 Markdown 转成抽象语法树（Abstract Syntax Tree，AST），rehype 把 AST 转成超文本标记语言（HyperText Markup Language，HTML），最后由 remark-rehype 衔接两端。安装依赖：

    终端
    npm install gray-matter remark remark-html remark-rehype unified rehype-highlight

    封装读取函数 lib/posts.ts

    我们把"读目录、解析 frontmatter、按日期排序"这一套收敛到 lib/posts.ts，列表页与详情页都从这里取数。注意它只在服务端运行（读文件系统），组件里不要用客户端导入。

    lib/posts.ts
    import fs from "node:fs";
import path from "node:path";
import matter from "gray-matter";
import { remark } from "remark";
import html from "remark-html";

const postsDirectory = path.join(process.cwd(), "content/posts");

export type PostMeta = {
  slug: string;
  title: string;
  date: string;
  description: string;
  tags: string[];
};

// 拿到所有文章的元数据（不含正文），按日期倒序
export function getSortedPosts(): PostMeta[] {
  const slugs = fs.readdirSync(postsDirectory);
  const posts = slugs
    .filter((f) => f.endsWith(".md"))
    .map((file) => {
      const slug = file.replace(/\.md$/, "");
      const full = path.join(postsDirectory, file);
      const { data } = matter(fs.readFileSync(full, "utf8"));
      return {
        slug,
        title: data.title,
        date: data.date,
        description: data.description ?? "",
        tags: data.tags ?? [],
      } as PostMeta;
    });
  return posts.sort((a, b) => (a.date < b.date ? 1 : -1));
}

// 取单篇文章：元数据 + 渲染好的 HTML 正文
export async function getPost(slug: string) {
  const full = path.join(postsDirectory, `${slug}.md`);
    if (!fs.existsSync(full)) return null;
  const { data, content } = matter(fs.readFileSync(full, "utf8"));
  const processed = await remark().use(html).process(content);
  return {
    slug,
    title: data.title as string,
    date: data.date as string,
    description: data.description as string,
    tags: (data.tags as string[]) ?? [],
    contentHtml: processed.toString(),
  };
}

    文章列表页

    列表页 app/blog/page.tsx 直接调用 getSortedPosts() 渲染卡片。因为它是服务端组件（Server Component），读文件系统在构建时就能完成。

    app/blog/page.tsx
    import Link from "next/link";
import { getSortedPosts } from "@/lib/posts";

export default function BlogIndexPage() {
  const posts = getSortedPosts();
  return (
    <main className="mx-auto max-w-2xl px-6 py-16">
      <h1 className="text-3xl font-bold">博客文章</h1>
      <ul className="mt-8 space-y-6">
        {posts.map((p) => (
          <li key={p.slug}>
            <Link href={`/blog/${p.slug}`} className="hover:underline">
              <span className="text-xl font-semibold">{p.title}</span>
            </Link>
            <p className="text-sm text-gray-500">{p.date}</p>
            <p className="mt-1">{p.description}</p>
          </li>
        ))}
      </ul>
    </main>
  );
}

    文章详情页与静态生成

    详情页用动态路由段 [slug]。关键在两个函数：generateStaticParams 在构建时返回所有要预渲染的文章 slug，generateMetadata 生成每篇文章的标题与摘要（SEO 细节见第 53 节）。二者结合，每篇文章在 next build 时被编译成纯静态 HTML。

    app/blog/[slug]/page.tsx
    import { notFound } from "next/navigation";
import { getPost, getSortedPosts } from "@/lib/posts";

// 构建时要预渲染哪些 slug
export function generateStaticParams() {
  return getSortedPosts().map((p) => ({ slug: p.slug }));
}

// 为每篇文章生成 metadata
export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) return { title: "文章不存在" };
  return { title: post.title, description: post.description };
}

export default async function PostPage({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) notFound();

  return (
    <article className="mx-auto max-w-2xl px-6 py-16">
      <h1 className="text-3xl font-bold">{post.title}</h1>
      <p className="mt-2 text-sm text-gray-500">{post.date}</p>
      {/* 正文由 remark-html 渲染成 HTML，这里直接注入 */}
      <div
        className="prose mt-8"
        dangerouslySetInnerHTML={{ __html: post.contentHtml }}
      />
    </article>
  );
}

    代码高亮与 MDX 直读简述

    代码高亮

    技术博客少不了代码块高亮。两种主流方案：一是 rehype-highlight（基于 highlight.js，接入简单），在 remark().use(rehypeHighlight) 一处即可；二是 Shiki（语法高亮引擎），对应 rehype-pretty-code，配色接近原生编辑器（VS Code 同款 TextMate 语法），视觉更好但构建略慢。把上例的 .use(html) 换成 .use(remarkRehype).use(rehypePrettyCode) 即可。

    MDX 直读

    当你想在文章里直接嵌入 React 组件（比如一张自定义的图表、一个提示框），就需要 MDX（Markdown + JSX）：文件后缀改为 .mdx，正文里可以写 <MyComponent />。第 30 节专门讲 MDX 配置，本节只需知道：Next.js 支持用 @next/mdx 插件把 .mdx 当成页面组件直接渲染，读取方式与 Markdown 几乎一致。

    常见坑：dangerouslySetInnerHTML 与 XSS›

    dangerouslySetInnerHTML 会把字符串当 HTML 注入。本文的 Markdown 来自你自己仓库里的可信文件，风险可控；但如果未来允许用户提交内容，必须先用 rehype-sanitize 做净化，否则存在跨站脚本攻击（Cross-Site Scripting，XSS）风险。另外 params 在 Next.js 15+ 是异步的，必须 await params，否则类型与运行都会报错。

    最佳实践›
    • slug 用文件名（如 hello-world.md → /blog/hello-world），简短、可读、对 SEO 友好，不要用随机 ID。
    • 日期统一用 YYYY-MM-DD 字符串，列表页排序才不会出错。
    • 文章内容放进 content/ 而非 app/，与路由代码分离，便于未来切换 Contentlayer、MDX 或 CMS。
    • 构建一次后所有页面都是静态的，配合第 56 节的 next build 输出，能看到每个 /blog/[slug] 被标记为 ○（静态）。
