    概念与背景：为什么 React Notes 需要认证

    前面 37-43 节我们把 React Notes 的列表、预览、编辑、搜索、国际化、上传都做完了，但有一个问题始终没解决：谁在写笔记？如果没有身份认证（Authentication，Auth），任何人打开页面都能看到、修改别人的笔记，这在真实产品里是不可接受的。本节就给 React Notes 接入登录能力。

    手写认证是一件非常繁琐的事：你要处理用户名密码哈希、会话（Session）管理、Cookie 安全标志、跨站请求伪造（Cross-Site Request Forgery，CSRF）防护、第三方登录跳转（OAuth 2.0 / OpenID Connect，OIDC）回调……而 NextAuth.js（自 v5 起品牌升级为 Auth.js）把这些都封装好了：一行配置就能接入 GitHub、Google、邮箱等几十种登录方式，并自动维护会话 Cookie。

    在 React Notes 的语境下，我们的目标是：用户用 GitHub 账号一键登录后，才能看到自己的笔记列表；未登录访问 /notes 自动跳转到登录页。

    点击"GitHub 登录"
    →
    跳转 GitHub 授权页
    →
    GitHub 回调本站
    /api/auth/callback
    →
    签发会话 Cookie
    →
    登录成功，访问笔记

    安装与环境变量

    Auth.js v5 目前以 beta 形式发布，包名仍是 next-auth，安装时加 @beta 标签。

    终端
    npm install next-auth@beta
# 自动生成 AUTH_SECRET 并写入 .env.local
npx auth secret

    然后在 GitHub 开放平台（github.com/settings/developers）注册一个 OAuth App，把 Client ID / Client Secret 填进环境变量：

    .env.local
    # 会话加密密钥（npx auth secret 自动生成）
AUTH_SECRET="随机长字符串"
# GitHub OAuth App 的凭证
AUTH_GITHUB_ID="Iv1.xxxxxxxxxxxx"
AUTH_GITHUB_SECRET="xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
# 本地开发地址
AUTH_URL="http://localhost:3000"
    注意：注册 OAuth App 时的回调地址›

    在 GitHub OAuth App 设置里，Authorization callback URL 必须填 http://localhost:3000 回调路径按规则生成（/callback/github）（生产环境换成你的域名）。填错会直接报 redirect_uri mismatch，这是新手第一大坑。

    核心配置：auth.ts

    v5 的最大变化是：所有配置集中在项目根目录的一个 auth.ts 文件里，从中解构出 handlers（路由处理器）、signIn、signOut、auth（取会话）四个能力，按需导出给服务端、客户端和中间件使用。

    auth.ts（项目根目录）
    import NextAuth from "next-auth"
import GitHub from "next-auth/providers/github"
import Google from "next-auth/providers/google"
import Credentials from "next-auth/providers/credentials"

export const { handlers, signIn, signOut, auth } = NextAuth({
  // providers 数组里每一项就是一种登录方式
  providers: [
    GitHub, // 自动读取 AUTH_GITHUB_ID / AUTH_GITHUB_SECRET
    Google({
      clientId: process.env.AUTH_GOOGLE_ID,
      clientSecret: process.env.AUTH_GOOGLE_SECRET,
    }),
    // 邮箱密码登录示例（生产环境要接数据库校验哈希密码）
    Credentials({
      credentials: {
        email: { label: "邮箱", type: "email" },
        password: { label: "密码", type: "password" },
      },
      async authorize(credentials) {
        // 这里应查询数据库校验密码；返回 null 表示登录失败
        if (credentials.email === "demo@example.com") {
          return { id: "1", email: credentials.email, name: "演示用户" }
        }
        return null
      },
    }),
  ],
  // 会话策略：默认 JWT（JSON Web Token），无需数据库也能跑
  session: { strategy: "jwt" },
  pages: {
    signIn: "/login", // 未授权时跳转到自定义登录页
  },
})

    挂载路由处理器

    Auth.js 需要一组标准接口（登录、回调、登出、取会话），在 App Router 里用一个路由处理程序（Route Handler）把 handlers 挂上去即可：

    app/api/auth/[...nextauth]/route.ts
    import { handlers } from "@/auth"
export const { GET, POST } = handlers

    这一个文件就自动提供了登录、第三方回调（callback）、读取会话（session）、退出登录（signout）等全部端点，统一挂在 /api/auth/ 前缀下，无需逐个手写。

    服务端取会话：auth()

    在 React Notes 的笔记列表页（服务端组件）里，用 auth() 直接拿到当前登录用户，不需要任何 Hook：

    app/notes/page.tsx
    import { auth } from "@/auth"
import { redirect } from "next/navigation"
import NoteList from "@/components/note-list"

export default async function NotesPage() {
  const session = await auth()
  // 未登录直接重定向到登录页
  if (!session?.user) redirect("/login")

  // session.user 里就有 id / email / name / image
  return (
    <main>
      <p>欢迎，{session.user.name}</p>
      <NoteList userId={session.user.id} />
    </main>
  )
}

    客户端：SessionProvider 与登录按钮

    客户端组件里要用 useSession() 读会话，必须先用 SessionProvider 包裹应用。新建一个客户端组件，挂到根布局里：

    app/providers.tsx
    "use client"
import { SessionProvider } from "next-auth/react"

export default function Providers({ children }: { children: React.ReactNode }) {
  return <SessionProvider>{children}</SessionProvider>
}
    app/layout.tsx
    import Providers from "./providers"

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh-CN">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  )
}

    登录 / 登出按钮则直接调用 signIn、signOut（v5 里它们可在客户端事件中直接使用）：

    components/auth-button.tsx
    "use client"
import { useSession, signIn, signOut } from "next-auth/react"

export default function AuthButton() {
  const { data: session, status } = useSession()

  if (status === "loading") return <p>加载中…</p>

  if (session) {
    return (
      <button onClick={() => signOut()}>
        退出登录（{session.user?.email}）
      </button>
    )
  }
  return <button onClick={() => signIn("github")}>使用 GitHub 登录</button>
}

    用中间件保护整组路由

    除了在页面里逐个判断，Auth.js 还支持把 auth 本身当作中间件，在请求到达页面之前就拦截未登录访问。注意：Next.js 16 起 middleware.ts 已改名为 proxy.ts；旧版本仍用 middleware.ts。

    middleware.ts（Next.js ≤15）/ proxy.ts（Next.js 16+）
    import { auth } from "@/auth"
import { NextResponse } from "next/server"

export default auth((req) => {
  const loggedIn = !!req.auth
  // 访问 /notes 下任何路径，未登录都踢回 /login
  if (!loggedIn && req.nextUrl.pathname.startsWith("/notes")) {
    const url = new URL("/login", req.url)
    url.searchParams.set("callbackUrl", req.nextUrl.pathname)
    return NextResponse.redirect(url)
  }
})

// 只对这些路由启用中间件
export const config = {
  matcher: ["/notes/:path*", "/dashboard/:path*"],
}

    App Router 与 Pages Router 用法对比

    NextAuth.js 在两种路由模式下的写法差异（以 v5 为准）
    能力App Router（本教程）Pages Router（旧写法）
    配置文件根目录 auth.ts，解构导出pages/api/auth 下的 [...nextauth] 路由里直接调 NextAuth(options)
    取会话（服务端）服务端组件里 await auth()getServerSideProps 里 getServerSession(...)
    取会话（客户端）useSession() + SessionProvider相同，_app.tsx 里包 Provider
    路由保护middleware.ts / proxy.ts_middleware.ts
    常见坑：中间件跑在 Edge Runtime，不能直连数据库›

    中间件运行在边缘运行时（Edge Runtime），不能使用 Prisma、bcrypt 等依赖 Node API 的库。如果用了数据库适配器（Adapter）持久化用户，把重数据库逻辑放在页面/路由处理程序里做，中间件只做"读 JWT、判断登录态"这种轻量判断。这也是为什么 session.strategy 用 JWT 而不是数据库查询时最顺。

    最佳实践：把 React Notes 的笔记按用户隔离›
    1. 所有笔记查询都带上 session.user.id 作为过滤条件，永远不要无条件查全表。
    2. 登录后跳转回来源页：登录页读 callbackUrl 参数，登录成功后 router.push(...)。
    3. 生产环境 AUTH_URL 必须配成真实域名，否则 HTTPS 下 Cookie 会写失败。
    4. 密码等敏感字段不要进 session.user，需要时用 callbacks.jwt / callbacks.session 手动挑选字段。
