实战篇 | React Hook Form 与表单处理

本节讲 React Hook Form：一个以非受控（Uncontrolled）为默认、用 Hook 管理表单状态的轻量库。我们从受控/非受控讲起，逐个拆解 useForm、register、handleSubmit、watch、errors、setValue，再配上 Zod 做声明式校验、用 Controller 包裹第三方受控组件，最后给一个可直接搬进 Next.js App Router 项目的完整注册表单。

    概念与背景

    React Hook Form（RHF）是一个以 Hook 为核心、体积约 10KB（压缩后）的 React 表单状态管理库。它解决的核心痛点是：用受控组件（Controlled Component）手写表单时，每敲一个字符都会触发整棵组件树重渲染，且要为每个字段手写 state、校验、错误收集。RHF 默认走非受控（Uncontrolled）路线——通过 register 把输入框直接注册到组件内部的引用（ref）上，取值时才从原生 DOM 节点读，从而把绝大多数输入过程挡在 React 渲染循环之外。

    在 Next.js 里，表单天然跑在客户端组件（Client Component）里（因为要处理交互与校验）；提交后既可以走传统的 fetch，也可以交给第 16-17 节讲过的 Server Actions。RHF 负责"前端采集 + 校验"，后端负责"持久化"，两者各司其职。

    受控 vs 非受控：为什么 RHF 快

    手写受控表单与 RHF 非受控表单的差异
    维度受控组件（useState 手写）RHF（默认非受控）
    状态存放每个字段一个 React state内部用 ref 收集原生 input
    输入时重渲染每次 keystroke 都重渲染组件不重渲染（提交/校验时才读值）
    错误收集手写 if/else 与错误对象由 resolver 或内置校验统一产出 errors
    代码量字段越多越冗长register 一行绑定一个字段
    第三方组件直接受控需要用 Controller 桥接
    用户输入
    （不触发渲染）
    →
    提交表单
    handleSubmit
    →
    resolver 校验
    （Zod / 内置）
    →
    通过：onSubmit(data)
    失败：写回 errors

    useForm 核心 API

    一切从 useForm 开始。它返回一组工具，最常用的是 register、handleSubmit、watch、setValue 与 formState.errors。

    app/register/RegisterForm.tsx（基础用法）
    "use client";
import { useForm } from "react-hook-form";

type FormValues = { email: string; password: string };

export function RegisterForm() {
  const {
    register,          // 把 input 注册进 RHF：{ onChange, onBlur, name, ref }
    handleSubmit,      // 校验通过后才会调用传入的 onSubmit
    watch,             // 监听某个字段的实时值（会触发当前组件重渲染）
    setValue,          // 编程式地设置某个字段的值
    formState: { errors, isSubmitting }, // 错误对象与提交状态
  } = useForm<FormValues>({
    defaultValues: { email: "", password: "" },
  });

  // watch 订阅 email 的实时输入（仅限确有需要时使用，避免无谓重渲染）
  const email = watch("email");

  async function onSubmit(values: FormValues) {
    // values 已经过校验，类型完整
    console.log(values);
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input type="email" placeholder="邮箱"
        {...register("email", { required: "邮箱必填" })} />
      {errors.email && <p>{errors.email.message}</p>}

      <input type="password" placeholder="密码"
        {...register("password", { minLength: { value: 6, message: "至少 6 位" } })} />
      {errors.password && <p>{errors.password.message}</p>}

      <button disabled={isSubmitting}>提交</button>
    </form>
  );
}
    useForm 返回值速查
    成员作用
    register(name, opts)把原生 input/select/textarea 绑进表单，返回要展开（spread）到元素上的 props。opts 里可写 required、minLength、pattern 等内置校验。
    handleSubmit(fn)包裹 onSubmit；校验未通过时不会调用 fn，并自动把错误写进 formState.errors。
    watch(name?)读取并订阅字段值；传参会监听单字段，不传返回整个表单值。注意它会触发重渲染。
    setValue(name, v)不经过用户输入、代码里直接改字段（如第三方地址自动填充）。
    formState.errors按字段名组织的错误对象，含 message。
    formState.isSubmitting提交进行中，用来禁用按钮防重复提交。

    与 Zod 配合做声明式校验

    内置校验适合简单表单；一旦规则复杂（跨字段比较、邮箱格式、嵌套对象），就把校验交给 Zod（第 63 节讲过的数据校验库），通过 @hookform/resolvers 的 zodResolver 接到 useForm 的 resolver 选项上。这样一份 schema 同时充当校验规则与TypeScript 类型来源。

    app/register/schema.ts
    import { z } from "zod";

export const registerSchema = z.object({
  name: z.string().min(2, "姓名至少 2 个字符"),
  email: z.string().email("邮箱格式不正确"),
  password: z.string().min(8, "密码至少 8 位"),
  confirm: z.string(),
}).refine((data) => data.password === data.confirm, {
  message: "两次输入的密码不一致",
  path: ["confirm"], // 错误挂在 confirm 字段上
});

// 从 schema 推导出表单的输入/输出类型
export type RegisterInput = z.input<typeof registerSchema>;
export type RegisterOutput = z.output<typeof registerSchema>;
    app/RegisterForm.tsx（接上，接入 resolver）
    "use client";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { registerSchema, type RegisterOutput } from "./schema";

export function RegisterForm() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm({
    resolver: zodResolver(registerSchema), // schema → resolver
    defaultValues: { name: "", email: "", password: "", confirm: "" },
  });

  async function onSubmit(values: RegisterOutput) {
    // values 已经是校验通过、经过 transform 的输出类型
    await fetch("/api/register", {
      method: "POST",
      body: JSON.stringify(values),
    });
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <input placeholder="姓名" {...register("name")} />
      {errors.name && <p className="err">{errors.name.message}</p>}

      <input type="email" placeholder="邮箱" {...register("email")} />
      {errors.email && <p className="err">{errors.email.message}</p>}

      <input type="password" placeholder="密码" {...register("password")} />
      {errors.password && <p className="err">{errors.password.message}</p>}

      <input type="password" placeholder="确认密码" {...register("confirm")} />
      {errors.confirm && <p className="err">{errors.confirm.message}</p>}

      <button disabled={isSubmitting}>{isSubmitting ? "提交中…" : "注册"}</button>
    </form>
  );
}

    Controller：包裹第三方受控组件

    RHF 默认用 ref 接管原生 input，但第三方组件（如日期选择器、下拉 Select、富文本）并不暴露原生 input ref，它们本身就是受控的（value + onChange）。这时要用 Controller 做一层桥接：它负责把 value/onChange 喂给第三方组件，并把结果写回 RHF 的内部状态。

    app/RegisterForm.tsx（Controller 示例）
    "use client";
import { useForm, Controller } from "react-hook-form";
// 假设使用 shadcn/ui 的 Select（第 64 节介绍过的组件库）
import { Select, SelectContent, SelectItem, SelectTrigger, SelectValue } from "~/components/ui/select";

type FormValues = { role: "user" | "admin"; birth: Date | null };

export function ProfileForm() {
  const { control, handleSubmit } = useForm<FormValues>({
    defaultValues: { role: "user", birth: null },
  });

  return (
    <form onSubmit={handleSubmit((v) => console.log(v))}>
      {/* Select 不是原生控件，必须用 Controller */}
      <Controller
        control={control}
        name="role"
        render={({ field }) => (
          <Select onValueChange={field.onChange} value={field.value}>
            <SelectTrigger><SelectValue placeholder="选择角色" /></SelectTrigger>
            <SelectContent>
              <SelectItem value="user">普通用户</SelectItem>
              <SelectItem value="admin">管理员</SelectItem>
            </SelectContent>
          </Select>
        )}
      />

      {/* 日期选择同理：field.value / field.onChange 直接对接 */}
      <Controller
        control={control}
        name="birth"
        render={({ field }) => (
          <input
            type="date"
            value={field.value ? field.value.toISOString().slice(0, 10) : ""}
            onChange={(e) => field.onChange(e.target.value ? new Date(e.target.value) : null)}
          />
        )}
      />
      <button>保存</button>
    </form>
  );
}

    与 Server Actions 结合（现代用法）

    在 App Router 下，提交不再一定要写 fetch。你可以把一个 Server Action 直接接到 handleSubmit 的回调里，由它把校验后的数据发到服务端做数据库写入与缓存重新验证。注意 Server Action 跑在服务端，拿不到 RHF 的浏览器 ref，所以 RHF 仍然只负责"客户端采集 + 校验"，Action 负责"服务端处理"。

    app/register/actions.ts（服务端二次校验）
    "use server";
import { registerSchema } from "./schema";

export async function registerAction(raw: unknown) {
  // 服务端再次校验（客户端校验可被绕过，服务端校验不可省）
  const parsed = registerSchema.safeParse(raw);
  if (!parsed.success) return { error: parsed.error.flatten().fieldErrors };

  // ... 写数据库、发验证邮件
  return { ok: true };
}

// 表单里：
// const onSubmit = (values: RegisterOutput) => registerAction(values);
// <form onSubmit={handleSubmit(onSubmit)}> ... </form>
    常见坑›
    • 忘记传 defaultValues：RHF 靠它知道有哪些字段。漏传会导致 reset、错误定位与某些重新渲染行为异常，控制台会有提示。
    • 滥用 watch：watch 会触发当前组件重渲染。一个表单里 watch 十几个字段，等于退回到受控模式。只有"确实需要实时联动"时才用，其余用 useWatch 隔离到子组件。
    • 把 errors 从 formState 里解构错：必须写成 formState: { errors }，直接 const { errors } = useForm() 拿不到。
    • 不写 noValidate：开启 resolver 后建议在 <form> 上加 noValidate，避免浏览器原生校验弹窗与 RHF 校验打架。
    最佳实践›
    1. 一份 Zod schema 两端复用：前端用 zodResolver，后端 Server Action / tRPC procedure 用同一个 safeParse，保证前后端校验规则永远一致。
    2. 字段越多越要拆分：大表单把每个字段抽成小组件，用 useWatch 订阅自己关心的字段，避免整表单重渲染。
    3. 提交按钮用 isSubmitting 禁用，防双击重复提交；同时在服务端做幂等。
    4. 样式库优先选"非受控友好"的：如 shadcn/ui 的表单组件自带 react-hook-form 适配（Form + Controller 封装），第 64 节有介绍。
