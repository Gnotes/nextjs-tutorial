    数据模型：Task 与 List 多对一

    在第 69 节 List 模型已加 tasks Task[] 关系的基础上，本节补出 Task 模型：一个任务属于一个清单，字段有标题、是否完成、所属清单 id。

    prisma/schema.prisma（追加 Task）
    model Task {
  id     String  @id @default(cuid())
  title  String
  done   Boolean @default(false)
  listId String
  list   List    @relation(fields: [listId], references: [id], onDelete: Cascade)
}

    tRPC 路由：task.create / toggle / delete

    关键安全点：创建或改任务前，要先确认该 listId 属于当前用户，否则用户 A 可以往用户 B 的清单里塞任务。我们抽一个小辅助函数校验清单归属。

    src/server/api/routers/task.ts
    import { z } from "zod";
import { TRPCError } from "@trpc/server";
import { createTRPCRouter, protectedProcedure } from "~/server/api/trpc";

// 校验清单属于当前用户，不属于则抛错
async function assertListOwned(db: any, listId: string, userId: string) {
  const list = await db.list.findFirst({
    where: { id: listId, ownerId: userId },
  });
  if (!list) throw new TRPCError({ code: "NOT_FOUND" });
}

export const taskRouter = createTRPCRouter({
  // 列出某个清单下的任务（支持按完成状态过滤）
  listByList: protectedProcedure
    .input(z.object({ listId: z.string() }))
    .query(async ({ ctx, input }) => {
      await assertListOwned(ctx.db, input.listId, ctx.user.id);
      return ctx.db.task.findMany({
        where: { listId: input.listId },
        orderBy: { done: "asc" }, // 未完成排前面
      });
    }),

  // 创建任务
  create: protectedProcedure
    .input(z.object({ listId: z.string(), title: z.string().min(1) }))
    .mutation(async ({ ctx, input }) => {
      await assertListOwned(ctx.db, input.listId, ctx.user.id);
      return ctx.db.task.create({
        data: { title: input.title, listId: input.listId },
      });
    }),

  // 切换完成状态
  toggle: protectedProcedure
    .input(z.object({ id: z.string() }))
    .mutation(async ({ ctx, input }) => {
      // 先找出任务并确认其清单归当前用户
      const task = await ctx.db.task.findUnique({
        where: { id: input.id },
        include: { list: true },
      });
      if (!task || task.list.ownerId !== ctx.user.id) {
        throw new TRPCError({ code: "NOT_FOUND" });
      }
      return ctx.db.task.update({
        where: { id: input.id },
        data: { done: !task.done },
      });
    }),

  // 删除任务
  delete: protectedProcedure
    .input(z.object({ id: z.string() }))
    .mutation(({ ctx, input }) => {
      return ctx.db.task.deleteMany({
        where: { id: input.id, list: { ownerId: ctx.user.id } },
      });
    }),
});

    页面交互：勾选、删除、按清单过滤、空状态

    页面顶部渲染第 69 节的清单列表，点击某个清单即按 listId 拉取它的任务；任务行用复选框勾选完成、按钮删除。完成后用 invalidate 失效对应查询缓存，界面自动刷新。

    src/app/TaskBoard.tsx（客户端组件）
    "use client";
import { useState } from "react";
import { trpc } from "~/trpc/react";

export function TaskBoard() {
  const [activeListId, setActiveListId] = useState<string | null>(null);
  const utils = trpc.useUtils();

  const { data: lists } = trpc.list.getAll.useQuery();
  const { data: tasks } = trpc.task.listByList.useQuery(
    { listId: activeListId ?? "" },
    { enabled: !!activeListId } // 未选清单时不发请求
  );

  const create = trpc.task.create.useMutation({
    onSuccess: () => utils.task.listByList.invalidate(),
  });
  const toggle = trpc.task.toggle.useMutation({
    onSuccess: () => utils.task.listByList.invalidate(),
  });
  const remove = trpc.task.delete.useMutation({
    onSuccess: () => utils.task.listByList.invalidate(),
  });

  const [title, setTitle] = useState("");

  return (
    <div>
      {/* 按清单过滤 */}
      <div className="lists">
        {(lists ?? []).map((l) => (
          <button key={l.id} onClick={() => setActiveListId(l.id)}>
            {l.name}
          </button>
        ))}
      </div>

      {activeListId && (
        <form onSubmit={(e) => {
          e.preventDefault();
          create.mutate({ listId: activeListId, title });
          setTitle("");
        }}>
          <input value={title} onChange={(e) => setTitle(e.target.value)}
            placeholder="新任务内容" />
          <button>添加任务</button>
        </form>
      )}

      {/* 任务列表 + 空状态 */}
      {!activeListId ? (
        <p>请先选择左侧的一个清单。</p>
      ) : (tasks ?? []).length === 0 ? (
        <p>这个清单还没有任务，添加一个吧。</p>
      ) : (
        <ul>
          {(tasks ?? []).map((t) => (
            <li key={t.id}>
              <input type="checkbox" checked={t.done}
                onChange={() => toggle.mutate({ id: t.id })} />
              <span style={{ textDecoration: t.done ? "line-through" : "none" }}>
                {t.title}
              </span>
              <button onClick={() => remove.mutate({ id: t.id })}>删除</button>
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}

    常见坑›
    • 越权写任务：不校验 listId 归属，就可能往别人清单里写数据。所有写操作前都要 assertListOwned。
    • 缓存不失效：改完任务若不 invalidate task.listByList，界面不会更新。读参数查询要用 invalidate() 而非手动改数据。
    • 未选清单就发请求：用 enabled: !!activeListId 关掉无效查询。
    • onDelete: Cascade：删清单时其下任务自动级联删除，无需手动清理。
    最佳实践›
    1. 把"资源归属校验"抽成可复用辅助函数（如 assertListOwned），各过程共用。
    2. 写操作成功后只 invalidate 受影响的查询，避免整站刷新。
    3. 空状态与未选状态要分开提示，引导用户下一步操作。
    4. 至此 67-70 节构成完整的 T3 Todo：初始化（67）→ 认证与主题（68）→ 清单（69）→ 任务（70），文件命名与变量保持一致。
