    概念与背景

    开发 UI 组件时，你常常遇到这些低效场景：想调一个 Button 的 hover 样式，得把整个应用跑起来、登录、点到那个页面；想确认空列表态长什么样，得手动把数据清空；设计同事问「这个组件有哪几种状态」，你说不清楚。Storybook 就是解决这些问题的组件隔离开发环境（Component Workbench）：它把组件从应用里单独拎出来，在一个沙盒页面里按「故事（Story）」一个个陈列出来。

    它带来三样东西：隔离开发（不依赖后端、路由、登录态）、可视化文档（组件的各种状态自动变成可点击目录）、以及配合插件做视觉回归与无障碍检查。它和第 64 节的 shadcn/ui、第 59 节的 Tailwind 是天然搭档。

    Storybook 的核心概念
    概念说明
    Story（故事）组件在某一种「参数组合」下的渲染快照，如「Button 的 disabled 态」就是一个 Story
    Args（参数）组件的 Props，声明后可在界面上实时调节，无需改代码
    Decorator（装饰器）包裹 Story 的通用布局（如加内边距、套主题 Provider）
    Addon（插件）扩展面板：无障碍检查、视口切换、主题切换、控件等

    Next.js + Storybook 集成

    在 Next.js 项目里安装并初始化，官方会帮你生成 .storybook/ 配置目录；关键是把框架指定为 @storybook/nextjs，这样 Storybook 才认识 Next.js 的图片组件、字体、路由别名。

    终端
    # 在现有 Next.js 项目里初始化 Storybook
npx storybook@latest init

    初始化完成后，核心配置长这样：

    .storybook/main.ts
    import type { StorybookConfig } from "@storybook/nextjs";

const config: StorybookConfig = {
  stories: [
    // 扫描项目里所有 .stories.tsx 文件
    "../components/**/*.stories.@(ts|tsx)",
    "../app/**/*.stories.@(ts|tsx)",
  ],
  addons: [
    "@storybook/addon-essentials",  // 含 controls / actions / viewport 等
    "@storybook/addon-a11y",        // 无障碍检查
    "@storybook/addon-links",
  ],
  framework: {
    name: "@storybook/nextjs",      // 关键：用 Next.js 框架适配
    options: {},
  },
};

export default config;

    由于你在 Next.js 里用 Tailwind，还需要在 Storybook 里把全局样式引入一次，否则组件会「裸奔」：

    .storybook/preview.ts
    // 引入项目的全局 CSS（含 Tailwind 指令），让 Story 里的类名生效
import "../app/globals.css";

import type { Preview } from "@storybook/react";

const preview: Preview = {
  parameters: {
    controls: { matchers: { color: /(background|color)$/i, date: /Date$/i } },
  },
};

export default preview;

    写一个 Story：Button.stories.tsx

    每个组件配一个同名 .stories.tsx 文件，用 Component Story Format (CSF) 导出：默认导出描述组件本身，命名导出是一个个 Story。

    components/ui/Button.stories.tsx
    import type { Meta, StoryObj } from "@storybook/nextjs";
import { Button } from "./Button";

// 默认导出：描述这个 Story 文件对应哪个组件
const meta: Meta<typeof Button> = {
  component: Button,
  title: "UI/Button",
  tags: ["autodocs"], // 自动根据 Props 生成文档
  argTypes: {
    // 在控制面板上把 onClick 标注为「事件」，点击时能看到参数
    onClick: { action: "clicked" },
  },
};
export default meta;

type Story = StoryObj<typeof Button>;

// 一个 Story = 一种参数组合
export const Primary: Story = {
  args: { variant: "primary", children: "保存" },
};

export const Disabled: Story = {
  args: { variant: "primary", children: "保存", disabled: true },
};

export const Outline: Story = {
  args: { variant: "outline", children: "取消" },
};

    对应的最小组件实现（Tailwind 类，呼应第 59 节）：

    components/ui/Button.tsx
    type Props = {
  variant?: "primary" | "outline";
  disabled?: boolean;
  children: React.ReactNode;
  onClick?: () => void;
};

export function Button({ variant = "primary", disabled, children, onClick }: Props) {
  const base = "rounded px-4 py-2 text-sm font-medium";
  const styles =
    variant === "primary"
      ? "bg-blue-500 text-white hover:bg-blue-600"
      : "border border-zinc-300 text-zinc-700 hover:bg-zinc-100";
  return (
    <button className={`${base} ${styles}`} disabled={disabled} onClick={onClick}>
      {children}
    </button>
  );
}

    常用 Addons 一览

    插件能帮你做什么
    Addon作用
    Controls界面上拖滑块 / 改颜色实时调整 Args，所见即所得
    Actions点击按钮时在面板打印事件参数，调试交互不用断点
    Viewport一键切换手机 / 平板视口，验证响应式
    a11y自动跑无障碍规则，标出对比度不足、缺少 label 等问题
    Links在 Story 之间跳转，模拟组件间导航
    常见坑：客户端组件 vs 服务端组件›

    Storybook 本质是在浏览器里跑客户端代码。如果你的组件用了 "use client" 或依赖服务端上下文（如直接 await 数据库），Story 里要把它当作纯展示组件、用 mock 数据喂 Props。需要展示服务端组件时，通常包一层传参的客户端容器。

    最佳实践：Story 即组件文档›

    给每个组件写 Story 时，刻意覆盖关键状态：loading、empty、error、disabled、超长文本。这些「边界态」往往正是设计评审和视觉回归最关心、而应用里最难手动触发的。Storybook 把它们固化下来，团队新人打开就懂这个组件能长什么样。
