实战篇 | React Notes | 侧边栏笔记列表

本节实现主界面的左半部分：用 React Server Component 直接读 SQLite，渲染可点击的笔记列表，加上「新建笔记」入口与加载骨架。你会看到 RSC 如何在服务端把数据和组件一次性拼好，浏览器拿到的是已经带数据的列表。

    要做什么

    React Notes 的界面是经典的主从布局（Master-Detail）：左边一栏是所有笔记的标题列表，右边是当前选中笔记的内容。本节先把左栏（侧边栏 Sidebar）做出来。它要满足四件事：

    • 从数据库读出全部笔记，按更新时间倒序排列（最近编辑的在最上面）；
    • 每条是一个链接，点击跳到 /notes/[id]；
    • 顶部有一个「新建笔记」按钮，点一下就建一条空笔记并跳转过去；
    • 数据还在加载时显示骨架屏，而不是白屏。

    双栏布局壳：app/notes/layout.tsx

    App Router 里，layout.tsx 是某段路由的共享外壳。我们把它放在 app/notes/ 下，于是 /notes、/notes/123、/notes/123/edit 都会共用这个左栏。这就是侧边栏只渲染一次、切换笔记时不闪烁的关键。

    app/notes/layout.tsx
    import Sidebar from "@/components/sidebar";

export default function NotesLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div style={{ display: "grid", gridTemplateColumns: "280px 1fr", minHeight: "100vh" }}>
      <Sidebar />
      <main style={{ padding: 24, borderLeft: "1px solid #ddd" }}>
        {children}
      </main>
    </div>
  );
}

    这里用 CSS Grid 分两列：左列固定 280px 放 <Sidebar />，右列 1fr 放 children（也就是各篇笔记页面）。

    服务端组件读取并渲染列表

    components/sidebar.tsx 是一个服务端组件（没有 "use client" 指令）。它可以直接调用 lib/db 里的同步查询函数——这是 RSC 的特权：数据获取和渲染发生在服务端，浏览器永远拿不到数据库句柄。

    components/sidebar.tsx
    import Link from "next/link";
import { getAllNotes } from "@/lib/db";
import NewNoteButton from "@/components/new-note-button";
import SearchBox from "@/components/search-box"; // 第 41 节再加，先占位

export default function Sidebar() {
  const notes = getAllNotes(); // 服务端直接查 SQLite

  return (
    <aside style={{ padding: 16, background: "#f7f7f8", height: "100vh" }}>
      <div style={{ display: "flex", justifyContent: "space-between", alignItems: "center" }}>
        <strong>Notes</strong>
        <NewNoteButton />
      </div>

      <div style={{ marginTop: 12 }}>
        <SearchBox />
      </div>

      <ul style={{ listStyle: "none", padding: 0, marginTop: 12 }}>
        {notes.map((note) => (
          <li key={note.id} style={{ marginBottom: 4 }}>
            <Link
              href={`/notes/${note.id}`}
              style={{ display: "block", padding: "8px 10px", borderRadius: 6, textDecoration: "none", color: "#222" }}
            >
              <div style={{ fontWeight: 600, fontSize: 14 }}>
                {note.title || "Untitled"}
              </div>
              <div style={{ fontSize: 12, color: "#888" }}>
                {new Date(note.updated_at).toLocaleString()}
              </div>
            </Link>
          </li>
        ))}
      </ul>
    </aside>
  );
}

    注意几点：用 next/link 的 <Link> 做导航而非 <a>，这样 Next.js 会做客户端导航（不整页刷新）；每条链接的 href 指向动态路由 /notes/[id]；列表项用 note.id 作 React 的 key，不要用数组下标。

    新建笔记：客户端按钮 + Route Handler

    「新建」按钮需要响应点击事件，而服务端组件里不能用 onClick、不能用 useState，所以它必须是一个客户端组件。它点击后向我们即将写的 Route Handler 发请求，创建成功后跳转到新笔记。

    components/new-note-button.tsx
    "use client";

import { useRouter } from "next/navigation";
import { useState } from "react";

export default function NewNoteButton() {
  const router = useRouter();
  const [pending, setPending] = useState(false);

  async function handleCreate() {
    setPending(true);
    try {
      const res = await fetch("/api/notes", { method: "POST" });
      const data = await res.json();
      // 跳转到刚建好的笔记
      router.push(`/notes/${data.id}`);
      router.refresh(); // 让服务端组件重新拉取列表
    } finally {
      setPending(false);
    }
  }

  return (
    <button onClick={handleCreate} disabled={pending} style={{ padding: "4px 10px" }}>
      {pending ? "…" : "+ 新建"}
    </button>
  );
}

    对应的 Route Handler 负责真正写库：

    app/api/notes/route.ts
    import { createNote } from "@/lib/db";

// POST /api/notes —— 新建一条空笔记
export async function POST() {
  const note = createNote();
  return Response.json({ id: note.id });
}
    点击「新建」
    →
    客户端 fetch
    POST /api/notes
    →
    Route Handler
    写 SQLite
    →
    返回新 id
    →
    router.push 跳转
    + refresh 刷新列表

    加载骨架：loading.tsx 与 Suspense

    首次进入或数据查询较慢时，Next.js 会在这段路由下就近寻找 loading.tsx，并自动用 React 的 Suspense 包裹页面。我们给列表加一个骨架屏：

    app/notes/loading.tsx
    // 这段路由在服务端渲染完成前，先显示这个占位 UI
export default function Loading() {
  return (
    <div style={{ padding: 24, color: "#888" }}>
      正在加载笔记列表…
    </div>
  );
}

    loading.tsx 本质就是"该路由段的 Suspense 兜底界面"。当列表数据 resolve 完，它会被真实内容无缝替换，配合流式渲染（Streaming）可以做到边下边展示。

    常见坑：服务端组件不能写交互›

    如果你在 sidebar.tsx 里直接写 onClick={...} 或 useState，Next.js 会报错：服务端组件没有浏览器环境。规则很简单——只有带 "use client" 的组件才能处理事件、用状态。所以「新建」这种交互拆成独立的客户端小组件，再嵌入服务端组件里。

    最佳实践：列表数据只查一次›

    侧边栏放在 notes/layout.tsx 里，意味着它在整个 notes 段只渲染一次，切换笔记时不会重复查库。配合 router.refresh() 在新建/保存后触发一次重渲染即可，避免每点开一篇笔记都重新拉一遍全量列表。

    提示：排序列用时间戳更省事›

    数据库里存的是毫秒时间戳（整数），排序直接 ORDER BY updated_at DESC 一次搞定，不必在应用层排序。展示时再用 new Date(ts).toLocaleString() 转成本地时间字符串。
