    T3 Stack 是什么

    T3 Stack 是一套以"全链路类型安全"为信仰的 Next.js 技术栈，由社区开发者 Theo Browne 推广开来。它的核心三件套是：TypeScript + tRPC + Tailwind CSS，并按需搭配 NextAuth（Auth.js）做认证、Prisma 做数据库访问。它的口号可以概括为"type-safe everything（处处类型安全）"——前端调后端、后端校验入参、数据库读写，全程都有 TypeScript 兜底。

    create-t3-app（官网 create.t3.gg）就是把这套栈"一键装好"的交互式脚手架：你在命令行里勾选需要的部分，它生成一个开箱即用、且已经把 tRPC Provider、Prisma、Auth 都接好的 Next.js 项目。

    T3 Stack 各角色
    技术在 T3 中的职责
    TypeScript贯穿前后端的类型系统，是 tRPC 端到端类型安全的地基。
    Next.js（App Router）应用框架，提供路由、React Server Components、部署能力。
    tRPC前后端之间的类型安全 API 层（第 66 节）。
    Tailwind CSS原子化 CSS 框架，负责样式。
    Auth.js（NextAuth）可选：认证与会话管理（第 68 节接入）。
    Prisma可选：类型安全的对象关系映射（Object-Relational Mapping，ORM），对接数据库（第 69、70 节建表）。

    常见坑›
    • 忘记配 .env：选了 Prisma 后必须填 DATABASE_URL，选了 Auth.js 必须有 AUTH_SECRET 与 OAuth 凭据，否则 prisma db push 或登录会直接报错。
    • 版本跟随：create-t3-app 会快速跟进 tRPC v11 / Auth.js v5，老博客里的 import 路径可能与生成代码不一致，以生成出来的代码和 create.t3.gg 官方文档为准。
    • 不要把它当黑盒：脚手架生成的每个文件都可读可改；改完结构后记得同步 root.ts 的路由合并。
    最佳实践›
    1. 初始化后先 pnpm dev 跑通默认首页，确认 tRPC 链路通了，再动手删示例代码。
    2. 把每个业务域（清单 list、任务 task）做成 routers/*.ts，在 root.ts 注册一行即可。
    3. 敏感过程统一挂 protectedProcedure，而不是在过程里手写鉴权。
    4. 后续三节（68-70）将在这个 t3-todo 项目上连续演进，注意文件路径与变量名前后一致。
