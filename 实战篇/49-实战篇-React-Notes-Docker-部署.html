    概念与背景：从"能跑"到"可维护的部署"

    第 48 节我们写出了官方多阶段 Dockerfile，镜像已经能跑起来。本节解决进阶问题：怎么让镜像更小、怎么把数据库和应用一起编排、怎么做健康检查和 CI/CD。核心武器是 Next.js 的 output: 'standalone' 输出模式。

    Standalone 输出：把运行时裁剪到最小

    默认 next build 产物里带着完整 node_modules，动辄几百 MB。开启 standalone 后，Next.js 会自动分析哪些文件是运行时真正需要的，只把它们打包进 .next/standalone 目录，体积通常能压到原来的几分之一：

    next.config.js
    /** @type {import('next').NextConfig} */
const nextConfig = {
  output: "standalone",
}
module.exports = nextConfig
    注意：standalone 不会自动包含 public/ 和 .next/static/，必须在 Dockerfile 里手动 COPY 这两个目录（第 48 节官方 Dockerfile 已经这么做了），否则样式和静态资源 404。

    docker-compose：应用 + 数据库一键编排

    React Notes 要连 PostgreSQL，用 docker-compose.yml 把 app 和 db 定义在一个文件里，一条 docker compose up 同时拉起两个容器、共享网络、共用环境变量：

    docker-compose.yml
    services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      # 服务名 db 就是容器间的主机名
      DATABASE_URL: "postgresql://postgres:postgres@db:5432/notes"
      AUTH_SECRET: "换成你的真实密钥"
    depends_on:
      - db
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: notes
    volumes:
      - pgdata:/var/lib/postgresql/data   # 数据持久化
    ports:
      - "5432:5432"
    restart: unless-stopped

volumes:
  pgdata:
    终端
    docker compose up --build      # 构建并前台启动
docker compose up -d           # 后台启动
docker compose logs -f app      # 看应用日志
docker compose down             # 停止并删除容器（数据卷保留）

    健康检查（HEALTHCHECK）

    让 Docker 主动探测容器是否真的活着，而不是"进程没退"就算健康。在 Dockerfile 末尾加一行：

    Dockerfile（追加）
    # 每 30 秒 curl 一次 3000 端口，失败 3 次标记 unhealthy
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD wget -qO- http://127.0.0.1:3000/ || exit 1

    容器在 docker ps 里会显示 (healthy) / (unhealthy)，配合编排系统就能自动重启故障容器。

    CI/CD 简单流程

    git push 到 GitHub
    →
    GitHub Actions
    构建镜像
    →
    推送镜像到
    镜像仓库
    →
    服务器拉新镜像
    docker compose up -d
    .github/workflows/deploy.yml（示意）
    name: Build and Push
on:
  push:
    branches: [main]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t ghcr.io/you/react-notes:latest .
      # 登录并推送（凭证放在仓库 Secrets 里）
      - run: echo "${{ secrets.GHCR_TOKEN }}" | docker login ghcr.io -u you --password-stdin
      - run: docker push ghcr.io/you/react-notes:latest

    服务器端只需定时或手动 拉新镜像并 up -d 即可更新。

    常见坑：depends_on 不等数据库真正就绪›

    depends_on: db 只保证 db 容器先启动，不保证 PostgreSQL 已经能接受连接。app 可能先起来、第一次连库就报 ECONNREFUSED。生产环境在 app 启动脚本里加重试，或用 wait-for-it 或 healthcheck 的 service_healthy 条件。

    最佳实践›
    1. 数据库数据一定挂 volume（pgdata），否则容器一删数据全没。
    2. 镜像打标签别只用 latest，用 Git commit hash 做不可变标签，方便回滚。
    3. 构建时把 .next/cache 挂成缓存卷，能显著加快二次 build。
