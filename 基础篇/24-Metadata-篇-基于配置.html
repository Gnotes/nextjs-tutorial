Metadata 篇 | 基于配置

本节讲 Next.js App Router 基于配置的 Metadata 体系：静态 metadata 导出、动态 generateMetadata()、title 模板继承、openGraph / twitter / robots / canonical 等字段，以及布局与页面之间的合并规则。Metadata 是搜索（Search Engine Optimization，SEO）与社交分享的基础。

    概念与背景：Metadata 是什么

    Metadata（元数据）指放在页面 <head> 里、不直接展示给用户，但描述页面"身份"的一组信息：浏览器标签页上的标题与图标、搜索引擎（Search Engine Optimization，SEO）读取的描述与关键词、社交平台分享时展开的卡片图、移动端的主题色等。它们决定了页面在搜索结果、社交分享、浏览器标签这些"页面之外"的场景里长什么样。

    在传统 React 项目里，你需要手动往 <head> 里塞 <title>、<meta> 标签；而 Next.js 的 App Router 提供了一套基于文件的元数据体系，并把它分成两类：

    • 基于配置（Config-based Metadata）：在 layout.tsx / page.tsx 里 export 一个 metadata 对象，或导出一个异步的 generateMetadata() 函数——这是本节的主题。
    • 基于文件（File-based Metadata）：用约定文件名（favicon.ico、opengraph-image.png、robots.ts 等）让框架自动生成对应标签——留到下一节讲。

    两者可混用：布局层写全局默认，页面层按路由覆盖。

    静态 Metadata：export const metadata

    在任意 layout.tsx 或 page.tsx 中导出一个常量对象，类型为 Metadata（来自 next）。框架会在构建时（或渲染时）把它转成对应的 <head> 标签。适合不依赖运行时数据的元数据。

    app/layout.tsx
    import type { Metadata, Viewport } from "next";

export const metadata: Metadata = {
  // 所有相对 URL（如 /og.png）都会拼到 metadataBase 前面
  metadataBase: new URL("https://example.com"),
  title: {
    default: "我的站点",          // 作为其他页面的兜底标题
    template: "%s | 我的站点",   // 子页面标题自动套用模板
  },
  description: "一个使用 Next.js App Router 构建的示例站点",
  keywords: ["Next.js", "React", "教程"],
  openGraph: {
    title: "我的站点",
    description: "基于 Next.js 的完整学习教程",
    url: "https://example.com",
    siteName: "我的站点",
    images: [{ url: "/og.png", width: 1200, height: 630 }],
    locale: "zh_CN",
    type: "website",
  },
  twitter: {
    card: "summary_large_image",
    title: "我的站点",
    description: "基于 Next.js 的完整学习教程",
  },
  robots: {
    index: true,     // 是否允许被索引
    follow: true,    // 是否允许爬虫跟踪链接
  },
  alternates: {
    canonical: "/",  // 规范链接（当前页的唯一官方 URL）
  },
};

// viewport 相关字段在 Next.js 14 起从 metadata 中拆出，单独导出
export const viewport: Viewport = {
  themeColor: "#0a0f1a",
};

    几个要点：

    • metadataBase 是"相对 URL 的基址"。设置之后，代码里写 "/og.png"，最终输出的绝对地址是 example.com/og.png；不设它，Next 会在构建/部署时发出相关警告。
    • alternates.canonical 用于告诉搜索引擎"这个页面的唯一地址是哪个"，避免带查询参数、多镜像地址造成重复内容问题。
    • openGraph（开放图谱协议）与 twitter 决定链接被分享到微信、X（原 Twitter）、Slack 等平台时展示的标题、描述和预览图。

    动态 Metadata：generateMetadata()

    当元数据要依赖当前路由参数或异步数据（例如一篇博客文章的标题来自数据库）时，就不能用静态常量了，要改用异步函数 generateMetadata()。它会拿到当前路由的 params（以及搜索参数 searchParams），可以在里面请求数据，再返回和 metadata 同形态的对象。

    app/blog/[slug]/page.tsx
    import type { Metadata } from "next";

// Next.js 15 起，params 是一个 Promise，需要 await
type Props = {
  params: Promise<{ slug: string }>;
};

export async function generateMetadata(
  { params }: Props,
): Promise {
  const { slug } = await params;

  // 从数据库或内容源读取文章
  const post = await getPost(slug);

  if (!post) {
    return { title: "文章未找到" };
  }

  return {
    title: post.title,
    description: post.excerpt,
    alternates: { canonical: `/blog/${slug}` },
    openGraph: {
      title: post.title,
      images: [post.ogImageUrl],
      type: "article",
    },
  };
}

// 真正渲染页面的组件同样 await params
export default async function Page({ params }: Props) {
  const { slug } = await params;
  // ...渲染内容
  return <article>...</article>;
}

    对比一下两种写法的选型：

    静态 metadata 与 generateMetadata 的选型
    写法适用场景特点
    export const metadata布局默认、固定的品牌信息、不依赖路由的页面纯静态，不产生额外请求，构建期可直接确定
    generateMetadata()动态路由详情页（文章、商品、用户主页）异步、可读数据库；与该页数据请求可被框架自动去重

    一个容易忽略的细节：generateMetadata 与 Page 组件里如果都 await getPost(slug)，Next.js 会按同一请求去重（请求备忘 / Request Memoization），不会真的发两次。

    title 与 title.template：模板继承

    标题是最能体现"布局向页面传递配置"的字段。在根布局里这样声明：

    app/layout.tsx
    export const metadata: Metadata = {
  title: {
    default: "我的站点",
    template: "%s | 我的站点",
  },
};

    然后在任意子页面：

    app/blog/page.tsx
    export const metadata: Metadata = {
  title: "博客列表",
};

// 最终 head 输出：<title>博客列表 | 我的站点</title>

    规则是：

    • 布局里的 template 会自动应用到所有后代页面返回的字符串标题上；default 则是"那些没有自己标题的页面"会用的兜底值。
    • 如果某个页面不想被模板污染，可以直接写成对象形式 title: { absolute }，它会原样输出、不套模板。
    layout 定义
    template: %s \\| 站点
    →
    page 给出
    title: "博客列表"
    →
    最终 title
    "博客列表 \\| 站点"

    常用字段速查

    Metadata 主要字段与对应 head 输出
    字段作用典型输出
    title浏览器标签页标题，可用模板<title>
    description页面摘要，搜索结果展示<meta description>
    keywords关键词列表<meta keywords>
    openGraph社交分享卡片（Open Graph 协议）og:* 系列 meta
    twitterX/Twitter 分享卡片twitter:* 系列 meta
    robots爬虫索引与跟踪指令<meta robots>
    alternates规范链接、多语言替代链接<link canonical>
    metadataBase相对 URL 的基址（不直接输出标签，用于拼绝对地址）
    viewport
    themeColor    		视口缩放、移动端主题色（Next 14 起独立导出）<meta theme-color>

    布局与页面的合并规则

    Metadata 沿路由树自顶向下合并：根布局写全局默认，子布局 / 页面按段覆盖。整体原则是页面层级的字段会覆盖布局层级的同名字段，而不是深合并。

    • title：唯一例外是 template 机制——子页面的字符串标题会被祖先布局的模板包裹。
    • description、openGraph、robots 等：页面一旦给出，就整体替换布局里的对应对象；如果只想补一个子字段，需要把要保留的字段也一并写全。
    • metadataBase 只需在最外层布局设一次，后代全部继承。
    常见坑：把 themeColor 写进 metadata›

    Next.js 14 起，metadata 里的 themeColor、viewport 字段被标记为废弃，应当改用独立的 export const viewport: Viewport 导出、在其中写 themeColor，动态场景则用 generateViewport()。继续写在 metadata 里仍能工作，但会收到弃用提示，且官方提供了 codemod（metadata-to-viewport-export）自动迁移。

    最佳实践：分层组织 metadata›
    1. 根布局只放全站级默认：metadataBase、title.template 与 default、全站 openGraph 默认图、viewport。
    2. 分段布局（如 app/blog/layout.tsx）放该段公共描述与默认标题。
    3. 具体页面只写自己独有的 title、description、canonical；动态详情页用 generateMetadata。
    4. 所有分享图统一放到 opengraph-image 文件约定（下一节会讲），避免在 metadata 里手拼图片地址。
