    概念：为什么不能直接用 img

    原生 <img> 有三个经典性能问题：图片尺寸不优化（桌面端也下载手机尺寸的图）、格式不现代（直接发 PNG/JPEG）、不懒加载导致首屏拥塞。Next.js 的 next/image 组件在原生 img 之上做了自动优化：

    • 自动格式转换：根据浏览器支持情况自动输出 WebP 或 AVIF，比 JPEG/PNG 体积小 25%-50%。
    • 响应式尺寸：同一图自动生成多种尺寸，浏览器按视口选择最合适的一张。
    • 懒加载（Lazy Loading）：默认只加载视口附近的图，滚动到才请求。
    • 布局稳定：通过 width/height 或 fill 提前占位，杜绝图片加载导致的布局抖动（Cumulative Layout Shift，CLS）。
    app/page.tsx
    import Image from "next/image";

export default function Page() {
  return (
    <Image
      src="/hero.jpg"
      alt="一张示例图"
      width={800}
      height={400}
      priority
    />
  );
}

    核心 Props 速查

    Image 组件常用属性
    属性作用说明
    src图片来源本地为 "/xx.jpg" 或 import 进来的对象；远程为完整 URL
    alt替代文本必填，无障碍与 SEO 需要
    width / height渲染尺寸（像素）决定布局占位比例；与实际文件大小无关
    fill填充父容器父元素需 position:relative；用于背景图、卡片封面
    sizes响应式断点提示配 fill 使用，告诉浏览器各断点下的显示宽度
    priority首屏优先加载关闭懒加载、预加载，LCP（Largest Contentful Paint）图必加
    quality压缩质量1-100，默认 75
    placeholder加载占位"blur" 显示模糊背景图（本地图自动生成 blurDataURL）

    本地图片：import 最省心

    放在项目 public/ 目录下的图片，以 /xxx.jpg 作为 src 引用；更推荐直接 import 图片文件，这样 width/height 会被自动推断，连尺寸都不用手写。

    app/page.tsx（本地图片）
    import Image from "next/image";
import hero from "@/assets/hero.jpg"; // 图片放在项目源码目录

export default function Page() {
  return (
    <main>
      {/* import 方式：自动带 width/height/alt 提示 */}
      <Image src={hero} alt="产品主图" placeholder="blur" />

      {/* public 目录方式：手写尺寸 */}
      <Image src="/avatar.png" alt="头像" width={64} height={64} />
    </main>
  );
}

    远程图片：必须配 remotePatterns

    为了防止恶意用户拿你的图片优化接口当开放代理滥用，Next.js 要求远程图片的域名必须在 next.config 里显式声明，否则运行时报错。

    next.config.js
    /** @type {import('next').NextConfig} */
const nextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "s3.amazonaws.com",
        pathname: "/my-bucket/**",
      },
      {
        protocol: "https",
        hostname: "cdn.example.com",
      },
    ],
  },
};

module.exports = nextConfig;
    app/gallery/page.tsx（远程图片）
    import Image from "next/image";

export default function Gallery() {
  return (
    <div className="grid">
      <Image
        src="https://s3.amazonaws.com/my-bucket/photo1.jpg"
        alt="远程照片"
        width={600}
        height={400}
        sizes="(max-width: 768px) 100vw, 600px"
      />
    </div>
  );
}
    常见坑：远程图未配 remotePatterns 报错›

    直接用 https://unknown.com/x.jpg 会看到类似 URL ... is not configured under images in your next.config.js 的错误。解决办法：在 images.remotePatterns 里把该域名（必要时细化 pathname）加进去，然后重启 next dev。生产环境切忌图省事用通配域名，有安全风险。

    fill：铺满父容器

    当你不知道最终渲染尺寸（如卡片封面、背景图）时，用 fill 让图片自动填满父元素。此时父元素必须 position: relative，并且不要再写 width/height。

    app/Card.tsx
    import Image from "next/image";

export default function Card() {
  return (
    <div className="card" style={{ position: "relative", width: "100%", aspectRatio: "16/9" }}>
      <Image
        src="/cover.jpg"
        alt="卡片封面"
        fill
        sizes="(max-width: 768px) 100vw, 50vw"
        className="object-cover"
      />
    </div>
  );
}

    与原生 img 对比

    next/image vs 原生 img
    维度next/image原生 img
    格式优化自动 WebP/AVIF原样发送
    尺寸适配多尺寸自动选择只有一份图
    懒加载默认开启需手动 loading="lazy"
    布局抖动width/height 或 fill 占位需自行预留
    LCP 图priority + preload手动处理麻烦
    远程图需声明白名单任意 URL
    最佳实践：图片加载策略›
    1. 首屏主图 / Logo / Banner 加 priority，否则懒加载会拖慢 LCP。
    2. 卡片列表图用 fill + sizes，并设 object-cover 保持比例。
    3. 本地图片优先 import，让构建自动推断尺寸与生成 blur 占位。
    4. 远程域名在 next.config 里按最小权限配置（精确到 pathname），不要用通配符域名。
