组件篇 | Link 和 Script

本节讲两个导航与脚本组件：next/link 在原生 a 标签之上做客户端导航、预取与滚动控制；next/script 用 strategy 控制第三方脚本的加载时机，避免拖慢首屏。

篇章：基础篇主题：组件对应小册：第 23 节

本节目录

    next/link：客户端导航组件

    next/link 是对原生 <a> 的封装：渲染出来的仍然是 <a> 标签，但点击时不会整页刷新，而是在浏览器端用 JavaScript 切换路由（客户端导航，Client-Side Navigation），同时自动预取（Prefetch）目标页面的代码，让跳转"秒开"。

    app/components/Nav.tsx
    import Link from "next/link";

export default function Nav() {
  return (
    <nav>
      {/* 字符串形式的 href */}
      <Link href="/about">关于我们</Link>
      <Link href="/blog">博客</Link>
    </nav>
  );
}

    动态路由的 href 构造

    链接到动态段（如 app/blog/[slug]/page.tsx）时，用模板字符串拼接 href，也可以传 URL 对象。

    app/blog-list/page.tsx
    import Link from "next/link";

const posts = [{ slug: "hello-next" }, { slug: "rsc-in-action" }];

export default function BlogList() {
  return (
    <ul>
      {posts.map((p) => (
        <li key={p.slug}>
          {/* 拼接动态段 */}
          <Link href={`/blog/${p.slug}`}>{p.slug}</Link>
        </li>
      ))}
    </ul>
  );
}

    常用 Props

    Link 常用属性
    属性作用说明
    href目标地址字符串或 URL 对象（{ pathname, query }）
    replace替换历史记录默认 false（push）；设 true 则浏览器后退键不回到当前页
    scroll跳转后是否滚动到顶部默认 true；表单提交后停留在原位时设 false
    prefetch是否预取目标页面默认 true（视口内的 Link 自动预取）；关闭可省流量
    app/checkout/success/page.tsx
    import Link from "next/link";

export default function Success() {
  return (
    <div>
      <p>下单成功！</p>
      {/* 替换历史：用户按后退键不会回到订单确认页 */}
      <Link href="/" replace>
        返回首页
      </Link>
    </div>
  );
}
    注意：Link 与 a 的关系›

    App Router 下 next/link 不再要求手动套 <a>：直接 <Link href="/x">文案</Link> 即可，组件自己会渲染 a 标签。要加 className、target 等原生属性，直接写在 Link 上即可透传。

    next/script：第三方脚本的加载时机

    广告、埋点、客服挂件等第三方脚本如果直接写进 <head>，会阻塞首屏渲染。next/script 通过 strategy 属性精确控制加载时机：

    • beforeInteractive：在页面可交互之前加载，用于核心 Vitals 相关脚本；通常放在根布局。
    • afterInteractive（默认）：页面水合（Hydration）之后立即加载，适合埋点、分析等不阻塞首屏的脚本。
    • lazyOnload：浏览器空闲时再加载，适合客服按钮、聊天挂件这类锦上添花的脚本。
    app/layout.tsx（第三方脚本）
    import Script from "next/script";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh-CN">
      <body>
        {children}
        {/* 埋点：水合后加载，不阻塞首屏 */}
        <Script
          src="https://analytics.example.com/script.js"
          strategy="afterInteractive"
          onLoad={() => console.log("analytics loaded")}
        />
        {/* 客服挂件：空闲时才加载 */}
        <Script
          src="https://chat.example.com/widget.js"
          strategy="lazyOnload"
        />
      </body>
    </html>
  );
}

    内联脚本与 JSON-LD

    不指向外部文件的内联脚本（如结构化数据 JSON-LD、计算逻辑），把内容直接放在 {"..."} 里。搜索引擎优化（Search Engine Optimization，SEO）常用的结构化数据就是典型场景。

    app/page.tsx（JSON-LD）
    import Script from "next/script";

export default function Page() {
  const jsonLd = {
    "@context": "https://schema.org",
    "@type": "WebSite",
    name: "我的博客",
    url: "https://example.com",
  };

  return (
    <main>
      <h1>首页</h1>
      {/* 内联 JSON-LD，帮助搜索引擎理解页面结构 */}
      <Script
        id="website-schema"
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
      />
    </main>
  );
}
    常见坑：beforeInteractive 只能放在根布局›

    beforeInteractive 策略的脚本必须放在 app/layout.tsx，放在页面里会被忽略或警告。绝大多数业务脚本用默认的 afterInteractive 即可；滥用 beforeInteractive 会拖慢首屏。

    最佳实践：导航与脚本约定›
    1. 站内跳转一律用 next/link，跨域外链才用原生 <a> 并加 target="_blank" rel="noopener"。
    2. 依赖浏览器历史状态的流程（下单成功、表单提交）用 replace 防止后退重现提交。
    3. 第三方脚本按重要性分级：埋点 afterInteractive、挂件 lazyOnload，只有必须的才 beforeInteractive。
    4. 内联脚本务必给 id，避免重复加载。
