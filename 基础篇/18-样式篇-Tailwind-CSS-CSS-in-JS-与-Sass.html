样式篇 | Tailwind CSS、CSS-in-JS 与 Sass

本节讲清 Next.js App Router 支持的五类样式方案：全局 CSS、CSS Modules、Tailwind CSS、Sass 与 CSS-in-JS。重点说明每种方案的接入方式、作用域规则，以及在 React Server Components (RSC) 与客户端组件中的使用边界。

    概念与背景：Next.js 支持哪些样式方案

    在普通 React 项目里，样式方案完全由你自己选型；而在 Next.js 中，框架为常见方案做了开箱即用的编译支持，你不需要手动配置 Webpack 或 PostCSS 就能直接写 CSS。App Router（应用路由器）下，官方推荐并原生支持的方案有五类：

    • 全局 CSS：在根布局 app/layout.tsx 中 import 一个普通 .css 文件，样式全局生效。
    • CSS Modules：以 *.module.css 命名的文件，自动做类名哈希，实现组件级样式隔离。
    • Tailwind CSS：原子化（Utility-First）CSS 框架，create-next-app 默认可选集成。
    • Sass：通过安装 sass 包，支持 .scss / .sass 语法与变量、嵌套。
    • CSS-in-JS：如 styled-components、@emotion 等；在 RSC 模型下需要额外处理，官方默认不内置。

    一个关键前提：全局 CSS 只能在根布局（或全局引入的文件）中导入，不能在任意组件中随意 import；而 CSS Modules 与 Tailwind 的类名可以在任何组件（包括服务端组件）中使用。这个区别是本节要反复强调的主线。

    五种样式方案横向对比（App Router）
    方案作用域能否用于服务端组件典型场景
    全局 CSS全局可（仅在 layout 中引入）重置样式、主题变量、基础排版
    CSS Modules组件级隔离可组件私有样式、避免类名冲突
    Tailwind CSS原子类，全局引入一次可快速开发、设计系统统一
    Sass全局或 Module（.module.scss）可（全局 scss 仍需在 layout 引入）需要变量/嵌套/混入的老项目
    CSS-in-JS运行时注入受限，需客户端组件 + 额外配置动态主题、高阶抽象

    全局 CSS：只能在根布局中引入

    新建项目时，app/layout.tsx 顶部已经有一行 import "./globals.css";。这就是全局样式的入口。规则很严格：全局 CSS 文件不能被 page、layout、component 等除根布局（及其向下共享链）之外的文件 import，否则构建报错。

    app/layout.tsx
    import type { Metadata } from "next";
import "./globals.css"; // 全局 CSS 只能放在根布局这里

export const metadata: Metadata = { title: "Next.js App" };

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh-CN">
      <body>{children}</body>
    </html>
  );
}
    app/globals.css
    :root {
  --brand: #38bdf8;
}

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  background: #0a0f1a;
  color: #d9e2f1;
}

.container {
  max-width: 880px;
  margin: 0 auto;
}
    常见坑：在普通页面里 import 全局 CSS›

    如果你在 app/about/page.tsx 里写 import "./reset.css"，构建会直接报错：Global CSS cannot be imported from files other than your Custom App / Root Layout。解决办法：把全局样式统一挪到 app/layout.tsx；只想给某个组件用的样式，改用 CSS Modules。

    CSS Modules：自动隔离的组件样式

    CSS Modules 通过文件名约定 *.module.css 触发。构建时，Next.js 会把里面的类名哈希成形如 Hero_module__title__x7Q2 的唯一类名，因此你在不同组件里都可以写 .title 而不会互相污染。使用时通过 styles.类名 引用。

    app/Hero.module.css
    .title {
  font-size: 1.8rem;
  color: var(--brand);
}

.card {
  padding: 16px;
  border: 1px solid #2a3a55;
  border-radius: 12px;
}
    app/Hero.tsx
    import styles from "./Hero.module.css";

export default function Hero() {
  return (
    <section className={styles.card}>
      <h1 className={styles.title}>CSS Modules 示例</h1>
    </section>
  );
}

    CSS Modules 在服务端组件与客户端组件中都能直接使用，因为它本质上只是"编译期改名 + 注入样式表"，不依赖运行时 JavaScript。类名动态拼接时可用模板字符串：className={`${styles.card} ${active ? styles.on : ""}`}。

    Tailwind CSS：官方默认集成方案

    Tailwind CSS 是一个原子化 CSS 框架——不写自己的类名，直接在 JSX 里写 flex、text-sm、bg-sky-500 这类工具类。从 Next.js 13 开始，create-next-app 提供 "Would you like to use Tailwind CSS?" 选项，选 Yes 后会自动完成全部配置，你几乎不需要手动写任何配置文件。

    手动接入时需要三个东西：

    1. 安装依赖：tailwindcss、postcss、autoprefixer（新版本可直接 npx tailwindcss init -p）。
    2. 生成 tailwind.config.ts 与 postcss.config.js。
    3. 在全局 CSS 中加入三条 @tailwind 指令。
    app/globals.css
    @tailwind base;
@tailwind components;
@tailwind utilities;

/* 可选：自定义主题变量 */
:root {
  --brand: theme("colors.sky.400");
}
    tailwind.config.ts
    import type { Config } from "tailwindcss";

export default {
  content: [
    "./app/**/*.{js,ts,jsx,tsx,mdx}",
    "./components/**/*.{js,ts,jsx,tsx,mdx}",
  ],
  theme: { extend: {} },
  plugins: [],
} satisfies Config;
    postcss.config.js
    module.exports = {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};
    app/page.tsx
    export default function Page() {
  return (
    <main className="mx-auto max-w-2xl p-6">
      <h1 className="text-2xl font-bold text-sky-400">用 Tailwind 写样式</h1>
      <p className="mt-2 text-slate-400">无需任何 CSS 文件。</p>
    </main>
  );
}
    提示：content 配置决定了哪些类会被打包›

    Tailwind 用 content 数组扫描源码，只有被扫描到的文件里出现过的类名才会生成对应 CSS，从而保持产物体积很小。新增目录（如 src/）时务必把路径补进 content，否则页面样式"神秘失效"。

    Sass：安装 sass 包即可

    Next.js 内置了对 Sass 的编译支持，但需要你自行安装官方的 sass 包。支持两种文件：普通 .scss / .sass（作为全局样式引入，规则同全局 CSS），以及 *.module.scss（作为 CSS Modules 使用，类名自动隔离）。

    安装
    npm install --save-dev sass
    app/variables.scss
    $brand: #38bdf8;
$radius: 12px;

.card {
  border-radius: $radius;
  padding: 16px;

  &:hover {
    border-color: $brand;
  }
}

    如果希望在多个 scss 文件中共享变量，Next.js 支持 next.config 中的 sass.additionalData 自动前置注入公共变量，避免每个文件手动 @use：

    next.config.js
    const nextConfig = {
  sassOptions: {
    additionalData: `@use "app/variables" as *;`,
  },
};

module.exports = nextConfig;

    CSS-in-JS：RSC 时代的现状

    CSS-in-JS 指在 JavaScript 里写样式的库，典型代表是 styled-components、@emotion、styled-jsx。在 Pages Router 时代这很常见；但在 App Router 的 RSC 模型下，这类库依赖运行时在浏览器中操作 DOM 并收集样式，而服务端组件不在浏览器执行、也不能使用浏览器 API，因此开箱即用会失败。

    官方文档的态度是：

    • Next.js 不内置任何 CSS-in-JS 方案的服务端渲染集成。
    • 要用 styled-components / @emotion 等，需自行配置 @emotion/react 的 "use client" 边界，并在客户端组件中使用。
    • 官方推荐：新项目优先 Tailwind CSS 或 CSS Modules；确需 CSS-in-JS 时，把样式相关组件隔离在客户端组件树内。
    app/Card.tsx（客户端组件中使用 @emotion）
    "use client";
import styled from "@emotion/styled";

const Box = styled.div`
  padding: 16px;
  border: 1px solid #2a3a55;
  border-radius: 12px;
`;

export default function Card({ children }: { children: React.ReactNode }) {
  return <Box>{children}</Box>;
}
    常见坑：在服务端组件里直接用 CSS-in-JS›

    styled-components / @emotion 在运行时订阅 React 渲染并生成样式表。当你在没有 "use client" 的文件中调用它们时，会出现样式丢失或水合（Hydration）警告。记住一条线：CSS-in-JS 只能用于客户端组件，服务端组件用 Tailwind / CSS Modules / 全局 CSS。

    选型建议与最佳实践

    新项目
    →
    Tailwind CSS
    （默认即可）
    →
    组件私有样式
    →
    CSS Modules / Sass Module
    最佳实践：项目内只主导一种方案›
    1. 新项目直接用 create-next-app 勾选 Tailwind，把它作为主力方案，全局只保留少量 globals.css 做重置与 CSS 变量。
    2. 需要深度定制的复杂组件，再用 CSS Modules（*.module.css），不要与 Tailwind 混用同一元素的两套类名。
    3. 从老 Sass 项目迁移时，把全局 scss 集中在 app/layout.tsx 引入，组件私有样式逐步改为 *.module.scss。
    4. 全局样式、Tailwind 指令、CSS 变量都只在根布局引入一次，避免重复加载。
