路由篇 | 链接与导航

next/link 的客户端导航、useRouter 编程式跳转、prefetch 与 RSC Payload 的工作方式。

篇章：基础篇主题：Link / useRouter对应小册第 04 节

本节目录

    概念与背景

    在传统多页应用里，点击链接意味着浏览器整页刷新：重新下载 HTML、重建 DOM（Document Object Model）、重新水合（Hydration）整个 React 应用。Next.js 提供客户端导航（Client-side Navigation）：点击 <Link> 后不刷新页面，而是在浏览器端切换路由、按需拉取新段所需的数据，体验接近单页应用（Single-Page Application，SPA），同时保留服务端渲染的好处。

    App Router 下客户端导航的核心是 RSC Payload（React Server Components 负载）：切换路由时，服务端并不会返回完整 HTML，而是返回一份精简的「服务端组件渲染指令流」（RSC Payload），客户端把它与已有的客户端组件树合并，只更新变化的部分。

    用户点击 Link
    →
    浏览器请求目标路由
    的 RSC Payload
    →
    客户端合并组件树
    保留未变布局状态
    →
    更新 URL 与视图
    无整页刷新

    next/link 的 Link 组件

    Link 是 App Router 下路由间导航的主要方式，它扩展了原生 <a>，自动带上 prefetch 与客户端导航能力。基本用法：

    app/page.tsx
    import Link from "next/link";

export default function HomePage() {
  return (
    <nav>
      {/* href 可以是字符串 */}
      <Link href="/about">关于我们</Link>

      {/* 也可以是对象：pathname + query */}
      <Link
        href={{ pathname: "/blog", query: { page: "2" } }}
      >第 2 页</Link>

      {/* 锚点：直达页面内某个 id */}
      <Link href="/docs#install">跳转到安装章节</Link>
    </nav>
  );
}

    原生 <a> 的属性（className、target="_blank" 等）会原样透传给底层 <a> 标签。

    Link 的关键 Props

    <Link> 常用 Props
    Prop默认值说明
    href必填要导航到的路径，字符串或 { pathname, query, hash } 对象
    replacefalse为 true 时替换浏览器历史栈当前项，而不是新增一条（用户点后退回不到来源页）
    scrolltrue为 false 时导航后不自动滚动到页面顶部；Next.js 默认会保持可见元素的滚动位置
    prefetchnull（即 "auto"）true 完整预取、false 不预取、auto 按静态 / 动态路由自适应

    编程式导航：useRouter

    在事件回调（按钮点击、表单提交、登录成功后跳转）里，用 next/navigation 导出的 useRouter() 做编程式导航。注意它只能在客户端组件里用（组件顶部加 "use client"）。

    app/components/LoginButton.tsx
    "use client";

import { useRouter } from "next/navigation";

export default function LoginButton() {
  const router = useRouter();

  return (
    <button
      onClick={() => {
        // 登录成功后跳转到仪表盘，并保留滚动位置
        router.push("/dashboard", { scroll: false });
      }}
    >
      登录并进入控制台
    </button>
  );
}

    router 对象的方法

    next/navigation 的 useRouter 返回值
    方法作用
    router.push(href, opts?)导航到新路由，并在浏览器历史栈新增一条记录
    router.replace(href, opts?)导航但替换历史栈当前项（等价于 Link 的 replace）
    router.refresh()用新的服务端请求刷新当前路由，重新拉取服务端组件数据，同时保留客户端状态与滚动位置
    router.back() / router.forward()浏览器历史后退 / 前进
    router.prefetch(href)手动预取目标路由，加速后续导航

    push / replace 的第二个参数支持 { scroll: false } 与 transitionTypes。

    App Router 与 Pages Router 的 useRouter 区别

    两个 useRouter 不要混用
    能力App Router：next/navigationPages Router：next/router
    导入路径next/navigation 导出的 useRouternext/router 导出的 useRouter
    路径名 / 查询串拆分给 usePathname()、useSearchParams() 等独立 Hook直接读 router.pathname、router.query
    路由事件用 usePathname 等组合监听router.events.on(...)
    典型方法push / replace / refresh / back / prefetchpush / replace / prefetch

    prefetch 行为详解

    预取（Prefetch）是 <Link> 进入浏览器视口时自动发起的后台请求，目的是让用户真正点击时路由已经「就绪」。官方文档明确：prefetch 只在生产环境（production）启用，开发环境不会预取。

    • prefetch={null}（默认，即 "auto"）：静态路由完整预取（含数据）；动态路由只预取到最近的 loading.tsx 边界为止。
    • prefetch={true}：无论静态动态都完整预取。
    • prefetch={false}：完全不预取。

    如果预取的数据在用户悬停前过期，Next.js 会在悬停时重新预取一次。

    常见坑›
    • 在服务端组件里调用 useRouter：useRouter 是客户端 Hook，组件顶部必须有 "use client"，否则运行时报错。
    • 混用 next/router 与 next/navigation：App Router 项目里从 next/router 导入的 useRouter 拿不到 App Router 的能力（refresh 等）。
    • 向 push 传入不可信 URL：javascript: 之类的 URL 会在当前页面上下文执行，带来跨站脚本（Cross-Site Scripting，XSS）风险；不要把用户输入直接塞进 push。
    • 期望导航后页面回到顶部却没生效：Next.js 的滚动策略是「保持可见元素位置」，需要回顶部请确认没有误传 scroll: false。
    最佳实践›
    1. 能声明式用 <Link> 就不要写 router.push；官方建议：除非有明确的事件逻辑，否则一律用 Link。
    2. 首屏重要的导航（顶部导航、主 CTA）保持默认 prefetch，让用户「想点就到」。
    3. 表单提交后跳转用 router.push(...) + router.refresh() 的组合：先切路由，再让服务端数据刷新。
    4. 粘性顶栏场景在 CSS 里设 scroll-padding-top，避免锚点跳转后内容被顶栏遮住。
