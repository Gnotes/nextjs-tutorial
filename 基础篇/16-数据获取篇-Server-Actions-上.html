    概念与背景

    传统 Web 应用里，「提交表单」需要你自己写一套：前端发超文本传输协议（HyperText Transfer Protocol，HTTP）请求 → 后端写接口（Route Handler / 服务端路由）→ 拿到响应再手动刷新界面。Server Actions（服务端动作）把这套链路压缩成一步：你写一个 async 函数，打上 'use server' 标记，它就运行在服务端，但可以像普通前端函数一样从表单、按钮、事件里调用。一次调用往返里，Next.js 既执行了你的服务端逻辑，又把最新的用户界面（User Interface，UI）一起返回。

    底层上，Server Action 是一个特殊的服务端函数（Server Function）：

    • 必须是 async function，因为它通过网络请求被调用。
    • 底层只用 POST 方法触发（不是 GET）。
    • 被传给 <form action> 或 <button formAction> 时，会自动被包裹进 startTransition。
    用户提交表单
    →
    浏览器 POST
    到 Server Action
    →
    服务端执行
    async 函数（写库）
    →
    服务端重新渲染
    当前路由
    →
    客户端直接呈现
    最新界面（无整页刷新）

    'use server' 指令与函数约定

    定义一个 Server Action 有两种方式：

    1. 文件顶部写 'use server'：该文件所有导出函数都是 Server Action（推荐，便于复用）。
    2. 函数体内写 'use server'：仅这个函数是 Server Action（只能在服务端组件里内联使用）。
    app/actions.ts（推荐：独立文件）
    'use server'
// 文件内所有 export 出来的 async 函数都是 Server Action

export async function createPost(formData: FormData) {
  const title = formData.get('title')
  const content = formData.get('content')
  // ...写入数据库...
  // ...后续 revalidate / redirect（见下节）...
}
    常见坑：'use server' 的位置与 async 约束›

    'use server' 必须是文件或函数体的第一条语句（前面不能有其他代码）。Server Action 必须是 async 函数，不能传普通函数值以外的不可序列化参数（不能把客户端函数、类实例传过去）。在客户端组件里不能定义 Server Action，只能从带 'use server' 的文件里 import。

    表单用法：直接绑定 action

    React 扩展了原生 <form>：把 Server Action 直接赋给 action 属性，提交时 Next.js 会自动把表单的 FormData 传给你的函数。

    app/actions.ts
    'use server'
import { revalidatePath } from 'next/cache'

export async function createPost(formData: FormData) {
  // FormData.get 按 input 的 name 取值
  const title = String(formData.get('title') ?? '')
  const content = String(formData.get('content') ?? '')

  // 1) 校验（生产中建议用 zod 等库）
  if (!title.trim()) throw new Error('标题不能为空')

  // 2) 写数据库（示意）
  await db.post.create({ data: { title, content } })

  // 3) 重新验证缓存，让列表页看到新数据
  revalidatePath('/blog')
}
    app/blog/NewPost.tsx
    import { createPost } from '@/app/actions'

// 服务端组件里直接绑定：input 的 name 决定 FormData 的键
export default function NewPost() {
  return (
    <form action={createPost}>
      <input name="title" placeholder="标题" />
      <textarea name="content" placeholder="正文" />
      <button type="submit">发布</button>
    </form>
  )
}

    注意：这个表单组件本身是服务端组件——不需要 'use client'。这就是 Server Actions 最优雅的地方：连客户端组件都不用写，表单就能工作。

    渐进增强：没有 JavaScript 也能提交

    Server Actions 天生支持渐进增强（Progressive Enhancement）：在服务端组件里绑定的表单，即使浏览器还没下载完 JavaScript、甚至用户禁用了 JavaScript，表单也能通过原生 POST 正常提交并工作。Next.js 在客户端 JavaScript 水合（Hydration）之后，再「接管」这次提交，避免整页刷新，换成无刷新的响应式交互。

    • 服务端组件表单：无 JS 可提交 → 水合后变无刷新。
    • 客户端组件表单：JS 未加载时提交会被排队，水合后优先执行；水合后提交不整页刷新。
    提示：这与传统 AJAX 表单的本质区别›

    传统写法里「无 JS」和「有 JS」是两套代码（原生 form 提交一套，AJAX 一套）。Server Actions 让你只写一套：默认就有降级能力，JS 就绪后自动升级体验。对低端设备、弱网、SEO 场景都友好。

    Server Actions vs Route Handlers：什么时候用哪个

    第 6 节讲过路由处理程序（Route Handler）：在 route.ts 里写 GET/POST... 函数。它和 Server Actions 都能在服务端执行逻辑，怎么选？

    Server Actions 与 Route Handlers 对比
    维度Server ActionsRoute Handlers（route.ts）
    设计目的表单提交、UI 变更后的写操作（mutations）对外暴露 API 接口、处理 Webhook
    调用方式由表单/按钮/事件触发，与组件树绑定任何客户端用 fetch 调，也可被第三方调用
    请求方法仅 POST支持 GET/POST/PUT/DELETE 等完整语义
    响应一次往返同时返回最新 UI返回你手动构造的 Response（JSON 等）
    典型场景发表评论、点赞、提交设置、写业务数据给手机/App 供接口、接收 GitHub/支付 Webhook
    一句话：「为当前应用的用户界面」服务的写操作用 Server Actions；「对外提供可编程接口」用 Route Handlers。

    完整示例：一个带客户端反馈的评论表单

    下面这个例子把服务端处理与轻量的客户端 pending 反馈拼起来——pending 细节在下一节展开，这里先建立整体感。

    app/actions.ts
    'use server'
import { revalidatePath } from 'next/cache'

export async function addComment(formData: FormData) {
  const postId = Number(formData.get('postId'))
  const body = String(formData.get('body') ?? '')
  if (!body.trim()) throw new Error('评论不能为空')

  await db.comment.create({ data: { postId, body } })
  revalidatePath(`/blog/${postId}`) // 刷新对应文章页
}
    app/blog/[slug]/Comments.tsx
    import { addComment } from '@/app/actions'

export default function Comments({ postId }: { postId: number }) {
  return (
    <form action={addComment}>
      {/* 隐藏字段携带上下文参数 */}
      <input type="hidden" name="postId" value={postId} />
      <textarea name="body" placeholder="写下你的评论…" />
      <button type="submit">提交评论</button>
    </form>
  )
}

    提交后发生的事：浏览器 POST 到服务端 → addComment 写库 → revalidatePath 使文章页缓存失效 → 服务端重新渲染 → 新评论直接出现在列表里，全程无整页刷新。

    最佳实践：Server Actions 落地清单›
    1. 把动作函数集中放在 app/actions.ts 或按领域拆分的 lib/ 文件里，文件首行 'use server'。
    2. 表单参数一律用 FormData.get 读取并做类型转换与校验，不要信任前端传值。
    3. 写完数据后立即 revalidatePath / revalidateTag，否则界面可能停留在旧状态（详见第 17 节）。
    4. 需要跳转就在动作里 redirect('/xxx')（它会抛一个框架控制流异常，之后的代码不会执行）。
