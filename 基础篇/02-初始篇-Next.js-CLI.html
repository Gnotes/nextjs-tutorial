初始篇 | Next.js CLI

从 create-next-app 到 next dev / build / start：用官方脚手架与命令行工具把项目跑起来。

篇章：基础篇主题：CLI 与脚手架对应小册第 02 节

本节目录

    概念与背景

    Next.js CLI（Command Line Interface，命令行界面）是 Next.js 官方提供的一套命令行工具，它做两件事：一是通过 create-next-app 一行命令从零生成一个配置齐全的项目；二是在项目内部通过 next dev / next build / next start 完成本地开发、生产构建与线上启动。

    为什么要用官方脚手架而不是手动建目录？脚手架替你把 TypeScript、ESLint（ECMAScript Linter）、Tailwind CSS、导入别名、Git 初始化、.gitignore 等约定一次配好，并且永远与当前官方文档同步。对新手而言，「先用脚手架跑通，再对照目录逐个文件理解约定」是成本最低的入门方式。

    两条命令路线

    • 创建项目：create-next-app——一个独立包，不需要全局安装，通过 npx / yarn / pnpm / bun 一次性执行。官方称它「零依赖（zero dependencies）」，初始化只需约一秒。
    • 项目内命令：next——项目安装 next 依赖后，通过 package.json 的 scripts 调用，负责开发服务器、构建与生产启动。

    create-next-app：创建项目

    不带参数运行会进入交互式提问，逐项确认技术选型：

    Terminal
    npx create-next-app@latest
# 随后依次提问：
# ? What is your project named? my-app
# ? Would you like to use TypeScript? No / Yes
# ? Would you like to use ESLint? No / Yes
# ? Would you like to use Tailwind CSS? No / Yes
# ? Would you like your code inside a `src/` directory? No / Yes
# ? Would you like to use App Router? (recommended) No / Yes
# ? Would you like to use Turbopack for `next dev`? No / Yes
# ? Would you like to customize the import alias (@/* by default)? No / Yes

    非交互参数一览

    把参数写全即可跳过提问，适合团队统一模板与 CI/CD（Continuous Integration / Continuous Deployment）自动化：

    create-next-app 常用参数（以官方文档 --help 输出为准）
    参数作用默认
    --ts / --typescript初始化为 TypeScript 项目默认开启
    --js / --javascript初始化为 JavaScript 项目—
    --tailwind集成 Tailwind CSS 配置默认开启
    --eslint集成 ESLint—
    --app使用 App Router 目录结构—
    --src-dir把源码放入 src/ 目录—
    --turbonext dev 默认使用 Turbopack 打包器—
    --import-alias <alias>自定义导入别名@/*
    --use-npm / --use-pnpm / --use-yarn / --use-bun显式指定包管理器自动检测
    -e, --example从官方示例名或 GitHub URL 初始化项目—
    --empty生成仅含最小骨架的空项目—
    --skip-install跳过依赖安装—
    --yes未显式指定的项全部沿用上次偏好或默认值—

    在任一参数前加 --no- 前缀即可关闭它，例如 --no-eslint、--no-src-dir。完整参数列表随时可运行 npx create-next-app@latest --help 查看。

    一条命令创建项目（完整示例）

    Terminal
    # 创建一个 TypeScript + Tailwind + App Router + src 目录的项目
npx create-next-app@latest my-blog \
  --typescript --tailwind --eslint --app \
  --src-dir --import-alias "@/*" --use-npm

cd my-blog
npm run dev
# 浏览器打开 http://localhost:3000

    脚手架生成的目录结构

    my-blog/
    my-blog/
├── app/                  # App Router：页面、布局、路由处理程序都放这里
│   ├── layout.tsx        # 根布局：必须包含 <html> 与 <body>
│   ├── page.tsx          # 首页（对应 URL /）
│   ├── globals.css       # 全局样式
│   └── favicon.ico
├── public/               # 静态资源：原样托管，不经过打包
├── next.config.ts        # Next.js 配置文件
├── package.json
├── tsconfig.json         # TypeScript 配置
├── eslint.config.mjs
└── README.md

    若创建时勾选了 --src-dir，app/ 会移动到 src/app/；public/ 与各类配置文件位置不变。

    package.json scripts

    官方脚手架生成的 scripts 大致如下，对应四个最常用命令：

    package.json
    {
  "scripts": {
    "dev": "next dev",      # 启动开发服务器（热更新 + 报错覆盖层）
    "build": "next build",  # 生成优化后的生产构建
    "start": "next start",  # 启动生产服务（必须先 build）
    "lint": "next lint"      # 运行 ESLint
  }
}

    若创建时选择了 Turbopack，dev 脚本会是 next dev --turbo。日常开发就是 npm run dev 这一条命令。

    next 命令族

    next 子命令速查
    命令作用典型场景
    next dev开发模式启动，带热更新（Hot Module Replacement，HMR）与全屏报错覆盖层日常本地开发
    next build生成优化后的生产构建，输出每条路由的体积报告上线前构建
    next start以生产模式启动已构建的应用（必须先 build）自托管部署
    next lint对 app / pages / components / lib / src 目录运行 ESLint提交代码前检查
    next info打印操作系统、Node 与包管理器版本、next/react 版本等环境信息向官方报 Issue 时粘贴
    next telemetry开启或关闭完全匿名的使用数据收集隐私 opt-out

    不带子命令直接运行 next 等价于 next dev。

    next dev 常用参数

    • -p, --port <port>：指定端口，默认 3000；也可以用环境变量 PORT=4000 next dev。
    • -H, --hostname <host>：指定监听地址，默认 0.0.0.0，便于局域网内其他设备（如手机）访问本机页面。
    • --turbo：使用 Turbopack（Webpack 的后继增量打包器）启动开发服务器，显著加快冷启动与热更新。
    • --experimental-https：本地生成自签 HTTPS 证书，用于 webhook、OAuth（Open Authorization）回调等必须走 https 的本地调试。

    next build 产物怎么读

    构建结束会打印一张路由表，告诉你每条路由的渲染方式与体积：

    Terminal（next build 输出示例）
    Route (app)                              Size      First Load JS
┌ ○ /                                    5.3 kB    89.5 kB
├ ○ /_not-found                          885 B     85.1 kB
└ ƒ /api/items                           0 B       0 B
+ First Load JS shared by all           84.2 kB

    其中 ○ 表示静态预渲染（Static，构建时生成 HTML），ƒ 表示动态渲染（Dynamic，请求时在服务端渲染）。Size 是客户端导航到该路由需下载的资源体积，First Load JS 是从服务端直接访问该页需下载的 JavaScript 体积，两者均为 gzip 压缩后的数值；首载 JS 建议保持在绿色区间。

    next start / next info / next telemetry

    • next start -p 4000：启动生产服务；注意它不能与 output: 'standalone' 或 output: 'export' 的配置搭配使用——standalone 模式用自带的 server.js，export 产出的是纯静态文件。
    • next info：把操作系统平台 / 架构、Node、npm、pnpm、yarn 版本，以及 next / react / react-dom 版本打印出来；按官方指引把这段信息粘贴到 GitHub Issue 里，能显著提高问题定位效率。
    • next telemetry disable：退出匿名遥测；next telemetry enable：重新开启。官方声明该收集完全匿名且可随时退出。
    常见坑›
    • PORT 不能写在 .env 里：HTTP 服务器在任何应用代码（包括加载 .env）之前就启动了，读不到 .env 中的 PORT。换端口请用 -p 参数或 shell 环境变量。
    • --turbo vs --turbopack：早期版本参数名为 --turbopack，新版文档统一为 --turbo；看老博客教程时务必核对 Next.js 版本号。
    • npx 缓存旧脚手架：固定写法 create-next-app@latest 可尽量避免拉到旧版；遇到奇怪提问顺序时先怀疑版本缓存。
    • Node 版本过低：Next.js 要求较新的 Node.js LTS（Long-Term Support，长期支持版），先 node -v 确认，过低会在 install 或 dev 阶段直接报错。
    最佳实践›
    1. 团队项目把「一整条 create-next-app 命令」写进 README，避免新成员靠点击提问攒出不一致的项目结构。
    2. 日常开发一律加 --turbo；本地需要 webhook / OAuth 时用 --experimental-https，不要自己折腾证书。
    3. 生产环境跑 next build && next start（或容器镜像），永远不要用 next dev 上线。
    4. 首次跑通脚手架后，对照本节的目录结构逐文件阅读，比直接啃配置文档高效得多。
