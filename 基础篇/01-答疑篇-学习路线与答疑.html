    概念与背景

    Next.js 是一个基于 React 的生产级 Web 框架，由 Vercel 团队维护，用于构建服务端渲染（Server-Side Rendering，SSR）、静态站点（Static Site Generation，SSG）、客户端渲染（Client-Side Rendering，CSR）等不同形态的 Web 应用。它开箱即用地提供了文件系统路由、代码分割、打包优化、数据获取、缓存与图片优化等能力，是当前社区使用最广泛的 React 全栈框架之一。

    本教程依据掘金小册《Next.js 开发指南》（冴羽）的 82 节目录重新编写，每一节都结合官方文档、社区博客与 GitHub 示例展开，力求「内容与目录一致」：目录里写的是什么，这一节就讲透什么。

    为什么需要学习路线

    Next.js 的生态庞大：路由、渲染、数据获取、缓存、Server Actions、Metadata、部署……如果漫无目的地刷文档，很容易迷失。先明确「你现在的水平」和「你要去的方向」，再按路线逐层推进，效率会高得多。本节给出的路线以官方 Learn 教程 和本书 82 节的结构为骨架，覆盖「基础 → 实战 → 源码 → 面试」四个阶段，与四大篇章一一对应。

    前置知识

    Next.js 不是一门全新的语言，它建立在 Web 基础之上。官方文档默认读者已经具备以下能力，建议在进入本书前先自测：

    • HTML / CSS：能写出语义化的页面结构，理解盒模型、Flexbox / Grid 布局与响应式设计的基本概念。
    • JavaScript 与 ECMAScript 模块（ES Modules，ESM）：理解异步编程（Promise、async/await）、解构赋值、import/export 等现代语法。
    • React 基础：组件、Props、状态（State）与副作用（Effect），以及受控组件等表单概念。官方建议先完成 React 官方学习路径。
    • Node.js 与 npm：能在命令行运行 node、npm 命令，理解依赖与脚本（Scripts）的概念。
    • TypeScript（推荐但可后补）：Next.js 对 TypeScript 有一等支持，本书第 29 节会专门讲解；不会也不影响先学基础篇。
    如果你完全没有 React 基础，直接学 Next.js 会同时面对「框架心智」与「React 心智」两座大山。官方文档的立场是：Next.js 面向"了解 React"的开发者。花一到两周补 React 基础，是性价比最高的投资。

    面试技巧 / 真题解析
    1. 基础篇（1-36）：按「路由 → 渲染 → 数据获取与缓存 → 样式与配置 → 组件与 Metadata → API」的顺序推进。其中第 8-12 节（渲染篇）和第 13-17 节（数据获取与缓存）是理解 Next.js 心智模型的核心，建议放慢节奏。
    2. 实战篇（37-70）：跟着 官方示例仓库 的 React Notes 与博客项目动手写代码，再做工具链（Clerk、Prisma、tRPC 等）组合练习。
    3. 源码篇（71-78）：用最小实现理解 SSR、静态站点生成（SSG）、增量静态再生成（Incremental Static Regeneration，ISR）、React Server Components (RSC)、Streaming 与 Server Actions 的原理。这个阶段不追求生产级代码，追求"知其所以然"。
    4. 面试篇（79-82）：回归面试视角，把前三个阶段的知识整理成可输出的答案，并补充沟通与答题技巧。

    环境准备：一条命令开始

    无论走哪条路线，第一步都是创建项目。官方脚手架 create-next-app 会交互式地询问 TypeScript、ESLint、Tailwind CSS、App Router 等选项，一次性完成项目初始化：

    终端
    # 创建项目（按提示选择 TypeScript / ESLint / Tailwind / App Router 等）
npx create-next-app@latest my-app

# 进入项目并启动开发服务器（默认 http://localhost:3000）
cd my-app
npm run dev

# 生产构建，以及本地以生产模式预览构建结果
npm run build
npm run start

    创建完成后，app/layout.tsx 是根布局、app/page.tsx 是首页，改动保存后浏览器会热更新。下一节（第 02 节）会完整讲解命令行接口（Command Line Interface，CLI）的每个命令与参数。

    高频答疑

    Q1：不学 React 能直接学 Next.js 吗？

    不建议。Next.js 的所有组件语法、Hooks 心智、状态管理都来自 React。官方文档的《Getting Started》假设读者已经了解 React，例如 react.dev/learn 被认为是进入 Next.js 之前的必读材料。至少掌握函数组件、useState、useEffect、Props 与条件渲染。

    Q2：App Router 和 Pages Router 学哪个？

    以 App Router 为主。App Router 是 Next.js 13 起默认的路由模型，官方文档以 App Router 为第一视角，新特性（React Server Components、Server Actions、加载与错误状态文件）都只在 App Router 下完整可用；Pages Router 仍受支持（Next.js 官方表示会继续维护），但官方建议新项目使用 App Router。本书全部章节基于 App Router 编写，涉及 Pages Router 差异时会单独标注。

    Q3：要不要用 TypeScript？

    推荐。Next.js 内置 TypeScript 支持（next dev 会自动识别 tsconfig.json），官方脚手架默认提供 TypeScript 选项，create-t3-app 等社区脚手架更是以类型安全为核心卖点。即使你刚入门，也可以先用 JavaScript 跑通，再逐步迁移。

    Q4：学习过程中要不要看源码？

    分阶段。基础阶段以"会使用"为目标，源码篇（71-78）专门用来建立原理认知。直接啃 vercel/next.js 的源码仓库对新手不友好，建议先完成实战篇再进入源码篇。

    注意点

    • Next.js 版本迭代快，文档以「当前稳定版」为准。本节及全书写作时以 App Router 稳定行为为依据，若你使用的版本较新，遇到 API 差异时优先查阅 官方文档 的版本说明。
    • 网络上的博客教程常有版本过期问题（例如还在讲 getServerSideProps、next export），学习时以官方文档为锚点，博客作为补充视角。
    • 不要在没搭好环境的情况下直接照抄生产项目配置（如复杂的 next.config.js），先在官方示例上跑通，再逐步叠加。
    最佳实践：如何高效使用本教程›
    1. 每节先读「本节目录」，明确这一节讲哪几个问题。
    2. 代码示例不要只看，逐个在你的本地项目里跑一遍；本书每节都给出可运行的示例文件路径。
    3. 遇到缩写（如 ISR、RSC），书中首次出现都会给出全称，例如增量静态再生成（Incremental Static Regeneration，ISR），陌生术语先看本节概念部分。
    4. 每节末尾的「参考链接」是追溯依据，遇到与别处资料冲突时，以官方文档链接为准。
