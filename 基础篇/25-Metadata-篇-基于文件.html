Metadata 篇 | 基于文件

本节讲另一类 Metadata：文件约定（File Conventions）。favicon、icon、apple-icon、opengraph-image、twitter-image，以及 robots.ts、sitemap.ts、manifest.ts——放对文件名，框架自动生成对应 head 标签或路由。

    概念与背景：为什么还要"基于文件"的 Metadata

    上一节讲的 export const metadata 适合写标题、描述这类文本配置。但有一类元数据是"文件"而不是"字段"：网站图标（favicon）、分享预览图、robots.txt、sitemap.xml、Web App Manifest……它们要么是一张图片，要么是一份要被搜索引擎抓取的特殊文本文件。

    Next.js 的做法是文件约定（File Conventions）：只要在某个路由段目录下放入约定命名的文件，框架就会自动生成对应的 <head> 标签或路由，你不需要手写一行代码。这就是"基于文件的 Metadata"。

    图标类：favicon / icon / apple-icon

    • app/favicon.ico：网站标签页图标。放在 app/ 根目录，框架会自动输出 <link rel="icon">，且 /favicon.ico 本身也可访问。
    • app/icon.(ico|jpg|jpeg|png|svg)：通用图标，可放在任意路由段（含子布局），支持多张、多尺寸。
    • app/apple-icon.(jpg|jpeg|png)：苹果设备"添加到主屏幕"时使用的图标（建议 180×180）。

    这些图片如果放在动态路由段，还可以写成生成式文件 icon.ts / opengraph-image.tsx，用代码在运行期生成图片（底层是 ImageResponse）。

    分享图：opengraph-image 与 twitter-image

    把一张图片命名为 opengraph-image.png 放到任意路由段目录下，框架就会自动输出对应的 Open Graph 标签：

    app/blog/opengraph-image.png（项目中的文件结构示意）
    app/
├── layout.tsx
├── page.tsx
└── blog/
    ├── page.tsx
    └── opengraph-image.png   // 自动生成 <meta property="og:image">

最终 head 输出（示例）：
<meta property="og:image" content="https://example.com/blog/opengraph-image.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
    • opengraph-image：用于 Facebook / 微信 / 通用社交分享卡片。
    • twitter-image：单独用于 X（Twitter）卡片；如果没单独写，会回退使用 opengraph-image。
    • 生成式写法 opengraph-image.tsx 可以按当前路由参数动态渲染一张图（例如把文章标题画到图上）。

    robots.ts：搜索引擎抓取规则

    在 app/robots.ts 导出一个对象，框架会在 /robots.txt 路径生成对应文本。相比手写静态文件，它可以读取运行期配置（如是否为生产环境）。

    app/robots.ts
    import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: "*",
      allow: "/",
      disallow: ["/private/", "/admin/"],
    },
    sitemap: "https://example.com/sitemap.xml",
    host: "https://example.com",
  };
}

// 最终访问 /robots.txt 输出：
// User-agent: *
// Allow: /
// Disallow: /private/
// Disallow: /admin/
// Sitemap: https://example.com/sitemap.xml

    sitemap.ts：站点地图

    同理，app/sitemap.ts 返回一个数组，框架会生成 /sitemap.xml。它非常适合配合数据层动态生成：从数据库读出所有文章 slug，拼成完整 URL 列表。

    app/sitemap.ts
    import type { MetadataRoute } from "next";

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const base = "https://example.com";

  // 从内容源取出所有文章
  const posts = await getAllPosts();

  const staticPages = ["", "/blog", "/about", "/contact"].map((p) => ({
    url: `${base}${p}`,
    lastModified: new Date(),
  }));

  const postPages = posts.map((post) => ({
    url: `${base}/blog/${post.slug}`,
    lastModified: post.updatedAt,
  }));

  return [...staticPages, ...postPages];
}

// 最终 /sitemap.xml 是标准 XML：
// <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
//   <url><loc>https://example.com/blog/hello</loc>...</url>
// </urlset>

    manifest.ts：Web App Manifest

    app/manifest.ts 返回 MetadataRoute.Manifest 对象，会生成 /manifest.webmanifest，用于 PWA（Progressive Web App，渐进式网页应用）场景：定义应用名、图标、主题色、启动方式等。

    app/manifest.ts
    import type { MetadataRoute } from "next";

export default function manifest(): MetadataRoute.Manifest {
  return {
    name: "我的站点",
    short_name: "站点",
    description: "示例 PWA",
    start_url: "/",
    display: "standalone",
    background_color: "#0a0f1a",
    theme_color: "#0a0f1a",
    icons: [
      { src: "/icon-192.png", sizes: "192x192", type: "image/png" },
      { src: "/icon-512.png", sizes: "512x512", type: "image/png" },
    ],
  };
}

    文件约定优先级与覆盖关系

    基于文件的 Metadata 约定一览
    约定文件名生成结果说明
    favicon.ico<link rel="icon"> + /favicon.ico仅 app/ 根目录生效
    icon.* / icon.ts<link rel="icon">可放在任意段，支持多文件、生成式
    apple-icon.*<link rel="apple-touch-icon">仅 jpg/jpeg/png
    opengraph-image.* / .tsxog:image 系列 meta可动态按路由生成
    twitter-image.*twitter:image 系列 meta无则回退 opengraph-image
    robots.ts / robots.txt/robots.txt文本型约定
    sitemap.ts / sitemap.xml/sitemap.xml可动态从数据库生成
    manifest.ts/manifest.webmanifestPWA 清单

    覆盖关系上：越靠近具体页面的文件约定，优先级越高。例如 app/opengraph-image.png 是全站默认，而 app/blog/opengraph-image.png 只对 /blog 及其子路由生效；更靠近页面的那个胜出。

    注意点：静态文件 vs 代码生成›

    同一类约定可以放静态文件（直接是 png/txt）也可以放代码文件（*.ts / *.tsx）。区别只在你需不需要运行期动态：图片固定就放 png；要按文章内容生成分享图，就写 opengraph-image.tsx。

    常见坑：robots/sitemap 和静态目录冲突›

    如果你在 public/ 目录下放了一个手写的 robots.txt 或 sitemap.xml，又同时在 app/ 里写了 robots.ts，两者会路由冲突（都指向同一 URL），构建时可能报错或后生效的覆盖先生效的。同一类文件二选一即可。

    最佳实践：图标与分享图统一命名›
    1. 全站默认图标放 app/icon.png，苹果图标放 app/apple-icon.png，旧版浏览器用 app/favicon.ico。
    2. 分享图建议 1200×630（Open Graph 标准比例），用 opengraph-image.png 命名放在 app/ 作为全站默认。
    3. 博客/商品详情页用 opengraph-image.tsx 按页面动态生成，避免为每篇文章手动做图。
