API 篇 | 常用函数与方法（上）

App Router 里最常用的一批函数：服务端侧的 cookies()、headers()、redirect()、permanentRedirect()、notFound()，客户端侧的 usePathname()、useSearchParams()、useRouter()。本节用表格逐个列出签名与用法，并标注 Next.js 15 的重要变化——这批服务端函数从同步改为返回 Promise。

    Next.js 15 的重要变化：服务端函数 Promise 化

    在逐个讲之前，必须先建立一个全局认知：从 Next.js 15（v15.0.0-RC）起，cookies()、headers() 以及页面的 params / searchParams 都从同步函数变成了异步函数，返回 Promise。v14 及更早它们是同步的。v15 为兼容旧代码仍允许同步调用，但将来会废弃，官方提供了 codemod 自动迁移。本节示例一律按 v15 的 await 写法给出。

    Next 15 异步化对照
    APIv14 及更早v15 起写法
    cookies()同步await cookies()
    headers()同步await headers()
    draftMode()同步await draftMode()
    页面 params直接取值await params
    页面 searchParams直接取值await searchParams

    cookies()：读取/写入请求 Cookie

    从 next/headers 导入。在服务端组件里只读；在服务端动作（Server Action）或路由处理程序里可读可写。它是请求期（Request-time）API，用在 layout/page 里会让路由进入动态渲染。

    cookies() 返回的 CookieStore 方法
    方法作用
    .get('name')取单个 cookie，返回 { name, value }。
    .getAll()取全部同名 cookie，返回数组。
    .has('name')判断某 cookie 是否存在。
    .set(name, value, opts)写 cookie（只能在服务端动作/路由处理器里）。
    .delete(name)删 cookie（同上限制）。
    app/page.tsx（读取）
    import { cookies } from 'next/headers'

export default async function Page() {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return <p>当前主题：{theme?.value ?? 'light'}</p>
}

    headers()：读取请求头

    同样从 next/headers 导入，返回一个只读的 Headers 对象（v15 起需 await）。常用于读取用户代理、地域、中间件注入的自定义头（如第 31 节的 x-nonce）：

    app/page.tsx
    import { headers } from 'next/headers'

export default async function Page() {
  const headersList = await headers()
  const userAgent = headersList.get('user-agent')
  return <p>UA：{userAgent}</p>
}

    redirect() 与 permanentRedirect()

    从 next/navigation 导入，在服务端组件/动作/路由处理器里触发跳转。redirect() 发 307（临时），permanentRedirect() 发 308（永久，利于搜索引擎优化，Search Engine Optimization，SEO）。它们抛出特殊异常中断渲染，所以调用后无需写 return：

    app/admin/page.tsx
    import { redirect, permanentRedirect } from 'next/navigation'
import { cookies } from 'next/headers'

export default async function AdminPage() {
  const cookieStore = await cookies()
  if (!cookieStore.get('session')) {
    redirect('/login')          // 未登录 → 临时跳登录
  }
  permanentRedirect('/home')    // 旧地址永久迁到新地址
  // ...
}

    notFound()：触发 404

    从 next/navigation 导入，调用后渲染最近的 not-found.tsx。常用于动态路由里找不到对应数据时：

    app/posts/[slug]/page.tsx
    import { notFound } from 'next/navigation'

export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  const post = await getPost(slug)
  if (!post) notFound()          // 渲染 not-found.tsx
  return <article>{post.title}</article>
}

    usePathname()：读当前路径（客户端）

    从 next/navigation 导入，在客户端组件里返回当前 URL 的路径名（不含域名、不含查询串）。常用于高亮当前导航项：

    app/components/Nav.tsx
    'use client'
import { usePathname } from 'next/navigation'

export function Nav() {
  const pathname = usePathname()   // 如 /blog/hello
  return <nav className={pathname === '/' ? 'active' : ''}>...</nav>
}

    useSearchParams()：读查询串（客户端）

    返回一个只读的 URLSearchParams 实例，读取 ?a=1&b=2 部分。

    app/search/page.tsx
    'use client'
import { useSearchParams } from 'next/navigation'

export default function SearchPage() {
  const searchParams = useSearchParams()
  const q = searchParams.get('q')   // ?q=next → 'next'
  return <p>搜索：{q}</p>
}
    常见坑：useSearchParams 与静态渲染的边界›

    useSearchParams() 在静态渲染（Static Site Generation，SSG）下会导致整棵树在构建期被强制放入客户端渲染边界。Next 要求把使用它的组件包进 <Suspense>，否则构建会报需要降级（de-opting）到动态渲染的警告/错误。这是迁移到 App Router 时最常见的报错之一。

    useRouter()：编程式导航（客户端）

    从 next/navigation 导入，返回路由对象，用于事件处理里做跳转、刷新、回退。注意 App Router 版的 useRouter 来自 next/navigation（不是 Pages Router 的 next/router）：

    app/components/BackButton.tsx
    'use client'
import { useRouter } from 'next/navigation'

export function BackButton() {
  const router = useRouter()
  return (
    <button onClick={() => router.push('/dashboard')}>
      去控制台
    </button>
  )
}
    useRouter() 常用方法
    方法作用
    router.push(href)导航到新路由（客户端跳转，不出整页刷新）。
    router.replace(href)替换历史记录（不留回退栈）。
    router.back()返回上一页。
    router.refresh()刷新当前路由服务端数据而不重置客户端状态。
    router.prefetch(href)预取路由（<Link> 默认已做）。
    最佳实践›
    1. 新代码统一写 await 版本，避免 v15 升级后同步调用被废弃。
    2. 能<Link>就别 useRouter.push；后者只用于表单提交、定时器等事件场景。
    3. 用 useSearchParams 的组件务必包 Suspense，否则 SSG 构建报错。
